# 가격 재확인 절차

화면에 보이는 가격은 사람이 판매처에서 확인한 참고가다. 확인일(`price_checked_at`)이 30일을 넘으면 `npm run check:release`가 실패해 배포가 막힌다(`src/lib/shared/limits.ts`의 `PRICE_MAX_AGE_DAYS`). 그 전에 이 절차로 다시 확인한다.

## 주기
- **30일마다** 전체 제품을 한 번에 확인한다. 기준일이 같아야 다음 확인일도 한 번에 돌아온다.
- 남은 날짜 확인: `npm run data:check -- --strict 2026-12-20`처럼 앞으로의 날짜를 넣어 돌리면 그날 실패할 제품이 미리 보인다.

## 확인할 곳
- 제품의 `sources`에 있는 **국내 판매처 상품 페이지**(지금은 20개 모두 피앤피노).
- 판매처가 바뀌거나 상품 페이지가 사라졌으면, 같은 모델을 파는 다른 국내 판매처를 찾아 출처를 바꾸고 메모에 남긴다.
- 해외 판매처 가격은 쓰지 않는다(배송비·관세가 달라 비교가 안 된다).

## 제품마다 기록할 것
| 항목 | 기준 |
|---|---|
| 판매가 | 할인이 적용된 지금 결제 가격(배송비 제외). 쿠폰·카드 할인·회원가는 넣지 않는다. 피앤피노는 "판매가"가 할인 전 가격이고 "할인가"가 실제 결제 가격이다. **할인가가 있으면 할인가를 쓴다**(2026-11-16 확인) |
| 옵션별 가격 | 옵션마다 다르면 우리 데이터의 모델(코어 두께·형태)에 해당하는 옵션의 가격. 색상만 다르면 가장 낮은 기본 가격 |
| 판매 상태 | 판매 중 / 일부 옵션 품절 / 전체 품절 / 상품 페이지 없음 |
| 확인일 | 실제로 페이지를 연 날짜(YYYY-MM-DD) |

## 바뀐 값 처리
1. 바뀐 가격과 판매 상태를 **확인표**로 정리해 사용자 승인을 받는다(전/후 가격, 변동률, 판매 상태, 확인한 페이지).
2. 승인 후 `price_krw`와 `price_checked_at`을 고친다. 가격이 그대로여도 `price_checked_at`은 확인한 날짜로 바꾼다.
3. 가격이 크게 바뀌어(대략 20% 이상) 예산 구간을 넘나들면, 추천 순위가 달라질 수 있으므로 전후 순위 비교를 함께 보고한다.
4. `npm run check:release`와 `npm run data:check -- --coverage`를 돌려 결과를 기록한다.

## 품절·단종
| 상태 | 처리 |
|---|---|
| 일부 옵션 품절 | 그대로 두고 메모에 적는다 |
| 전체 품절(재입고 예정) | 그대로 두고 메모에 "품절(확인일)"을 적는다. 다음 확인 때 다시 본다 |
| 2회 연속 품절이거나 상품 페이지 없음 | 다른 국내 판매처를 찾는다. 없으면 `paddles.json`에서 빼서 `data/staging`의 초안으로 되돌리는 것을 사용자에게 제안한다 |

## 기록
- 확인할 때마다 결정 기록(`docs/decisions.md`)이 아니라 커밋 메시지에 "가격 재확인 YYYY-MM-DD, 변경 N개"로 남긴다.
- 판매처 이용약관에 자동 수집 금지 조항이 있을 수 있으므로 가격은 사람이 페이지를 열어 확인한다(자동 수집하지 않는다, 2단계 기획안 4장).
