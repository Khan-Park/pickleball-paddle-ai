# UI 흐름 설계 (v0.1 초안, 2026-11-15)

질문에 답하면 추천 3개를 이유와 함께 보여 주는 화면 흐름. 엔진(`src/lib/recommend`)과 데이터(`data/paddles.json`)는 이미 있다. 이 문서는 화면과 데이터 흐름만 다룬다. 코드는 없다.

## 1. 화면 3개
| 경로 | 화면 | 내용 |
|---|---|---|
| `/` | 시작 | 한 줄 소개, "1분 질문으로 맞는 패들 찾기" 버튼, 추천 방식 안내(스펙 기준, 광고 수수료가 순위에 영향 없음) |
| `/quiz` | 질문 | 한 화면에 질문 하나. 진행 표시, 이전·다음 |
| `/result` | 결과 | 추천 3개 카드, 주의 문구, 안내·고지. 후보가 없으면 조건 완화 제안 |

회원가입, 저장, 공유는 MVP에서 뺀다(명세의 MVP 제외 항목).

## 2. 질문 흐름 (최대 7개)
| 순서 | 질문 | 선택지 | 프로필 필드 | 비고 |
|---|---|---|---|---|
| 1 | 피클볼이나 라켓 운동 경력은? | 처음·1년 미만 / 1~3년 / 3년 이상 | skill_level | 초보·중급·상급으로 변환 |
| 2 | 어떤 플레이가 더 중요한가요? | 정확한 컨트롤 / 균형 / 강한 파워 | play_style | 초보에게는 "잘 모르겠어요 → 균형" 선택지 추가 |
| 3 | 패들 무게는 어떤 쪽이 좋나요? | 가볍게 / 중간 / 묵직하게 / 상관없어요 | weight_preference | 기본 선택은 "상관없어요" |
| 4 | 팔·손목·팔꿈치가 불편한 적이 있나요? | 있어요 / 없어요 | arm_discomfort | 질문 아래에 "의학적 조언이 아닙니다" 한 줄 |
| 5 | 선호하는 패들 모양이 있나요? | 그림과 함께 4가지, 여러 개 선택, "건너뛰기" | preferred_shapes | **초보는 이 질문을 건너뛴다**(용어를 모를 가능성이 높다) |
| 6 | 예산은 어느 정도인가요? | 10만 원 이하 / 10~20만 / 20~30만 / 상관없어요 | budget | 직접 입력은 MVP에서 뺀다 |
| 7 | 대회에 나갈 계획이 있나요? | 네(USA Pickleball 승인 제품만) / 아니요·모르겠어요 | needs_certification | "네"를 고르면 승인이 확인된 제품만 나온다고 안내 |

- 진행형 규칙은 두 가지뿐이다: 초보는 5번을 건너뛰고, 2번에 "잘 모르겠어요"가 추가된다. 규칙이 많으면 테스트와 유지가 어렵다.
- 답을 고르면 바로 다음 질문으로 넘어간다(5번만 "다음" 버튼). 이전으로 돌아가 고칠 수 있다.
- 답변 → `UserProfile` 변환은 순수 함수로 만들고 `parseUserProfile`로 검증한다.

## 3. 결과 화면
**추천 카드(최대 3개)**
- 순위, 브랜드·모델명, 적합도 라벨(매우 잘 맞음 / 잘 맞음 / 보통). 점수 숫자는 보여 주지 않는다.
- 추천 이유 1~3개(엔진의 `reasons`), 주의 문구(엔진의 `cautions`)는 색을 달리해 따로.
- 스펙 요약: 무게, 코어 두께, 형태, 길이×폭.
- 가격: "약 000,000원 (2026-11-15 기준, 판매처에 따라 다름)". 가격 확인일이 30일을 넘었으면 "가격 변동 가능" 표시.
- 대회 승인: 확인된 제품만 "USA Pickleball 승인 확인(확인일)" 배지. 미확인은 "승인 여부 미확인"으로 적고 숨기지 않는다.
- 구매 링크: `purchase`가 있을 때만 버튼을 보여 주고, **바로 옆에 대가 표시**("이 링크로 구매하면 수수료를 받을 수 있습니다")를 둔다(CLAUDE.md 규칙 3). 지금은 모든 제품의 링크가 비어 있어 버튼이 나오지 않는다.

**화면 공통 안내**
- "제조사·판매처가 공개한 스펙을 기준으로 한 추천입니다. 실제 타구감은 사람마다 다릅니다."
- 그립 고르는 법 안내(접이식).
- 팔 불편을 고른 경우: "불편을 줄이는 데 도움이 될 수 있는 사양을 우선했습니다. 통증이 계속되면 전문가와 상담하세요."(의학적 효과를 단정하지 않는다)
- "수수료는 추천 순위에 영향을 주지 않습니다."

**후보가 없을 때**
- 엔진의 조건 완화 힌트를 버튼으로 보여 준다. 예: "예산을 129,000원으로 올려서 다시 보기". 누르면 그 조건만 바꿔 다시 계산한다.

**추천이 3개보다 적을 때**는 있는 만큼만 보여 주고 이유를 한 줄로 알린다.

## 4. 데이터 흐름
```
서버(페이지)                          브라우저
data/paddles.json 읽기 → 검증
  ├─ PaddleSpec[] (purchase 제거) ──→ recommend(specs, profile, {today})
  └─ 표시용 정보(id → 이름·가격·purchase) ──→ 결과 카드가 paddle_id로 찾아 표시
```
- 엔진에는 `purchase`가 없는 `PaddleSpec`만 넘긴다. 구매 링크는 결과가 나온 뒤 `paddle_id`로 붙인다. 순위 계산이 링크 유무를 볼 방법이 없다(규칙 1).
- 추천 계산은 브라우저에서 한다. 엔진이 순수 함수이고 제품이 수십 개라 서버 왕복이 필요 없다.
- 기준일(`today`)은 화면이 넘긴다. 엔진은 현재 시각을 읽지 않는다.
- **답변 보관**: 브라우저의 `sessionStorage`에 둔다. 팔 불편 답변은 건강 관련 정보이므로 URL 쿼리에 넣지 않는다(주소 공유·기록으로 새지 않게). 탭을 닫으면 사라진다. 서버로 보내지 않는다.
- `/result`에 답변 없이 들어오면 `/quiz`로 보낸다.

## 6. 화면 원칙
- 모바일 우선(폭 360px에서 한 손으로 조작). 선택지는 세로로 쌓는다.
- 한국어. 전문 용어에는 한 줄 풀이(예: "코어 두께: 두꺼울수록 컨트롤, 얇을수록 파워").
- 색만으로 구분하지 않는다(주의 문구는 아이콘과 글자 함께). 키보드와 화면 낭독기로 끝까지 진행 가능.
- 로딩 화면이 필요 없다(계산이 즉시 끝남).

## 7. 검증
- 답변 → 프로필 변환, 초보 분기 규칙은 단위 테스트.
- 화면 컴포넌트 테스트는 새 패키지(`@testing-library/react`, `jsdom`)가 필요하다. 설치 전에 승인을 받는다. 승인 전에는 로직 테스트와 브라우저에서 직접 확인으로 한다.
- 확인 시나리오: 초보 흐름(질문 6개), 상급 흐름(7개), 후보 0개(예산 10만 이하 + 대회용), 팔 불편 안내 표시, 구매 링크 없는 카드.

## 8. 작업 분해
- T-009 질문 정의와 답변 → 프로필 변환(순수 함수, 테스트). 화면 없음
- T-010 시작·질문 화면(`/`, `/quiz`)
- T-011 결과 화면(`/result`): 카드, 안내, 조건 완화
- T-012 대가 표시·대회 승인 배지·고지 문구 점검(구매 링크가 생기기 전에 틀을 완성)

## 9. 확정된 결정 (사용자 확정 2026-11-15)
1. 질문 7개와 초보 분기 두 가지(5번 건너뛰기, 2번에 "잘 모르겠어요")
2. 예산은 구간 선택만(직접 입력 제외)
3. 답변은 `sessionStorage`에만 두고 결과 공유 기능은 MVP에서 뺀다
4. 구매 링크가 없는 동안 결과 카드는 버튼 없이 가격과 스펙만 보여 준다
5. 화면 컴포넌트 테스트용 패키지(`@testing-library/react`, `jsdom`)를 설치한다. 실제 설치는 T-010을 시작할 때 버전을 확인하고 한다
6. 화면 분위기는 차분하고 신뢰감 있는 톤(아래 10장)

미정: 서비스 이름, 브랜드 색, 다크 모드(MVP는 밝은 화면만).

## 10. 화면 분위기: 차분하고 신뢰감 있는 톤
비교·분석 서비스처럼 보이게 한다. 스포츠 쇼핑몰의 들뜬 느낌이 아니라 "근거를 보여 주는 추천"이 중심이다.
- **색**: 짙은 남색을 기본 색으로, 회색 계열을 바탕과 보조로 쓴다. 강조색은 하나만 둔다(선택된 답, 주요 버튼). 주의 문구는 주황 계열, 대회 승인 확인은 초록 계열로 구분하되 아이콘·글자와 함께 쓴다.
  - 초안 값(구현 때 명도 대비 4.5:1 이상인지 확인해 조정): 남색 `#1E2A44`, 강조 `#2F6FED`, 바탕 `#F6F7F9`, 카드 `#FFFFFF`, 본문 글자 `#1F2937`, 보조 글자 `#6B7280`, 경계선 `#E5E7EB`, 주의 `#B45309`, 확인 `#15803D`
- **글자**: 시스템 기본 한글 글꼴. 숫자와 스펙은 고정폭 숫자로 줄을 맞춘다. 굵기는 2단계만 쓴다.
- **구성**: 흰 카드, 얇은 경계선, 그림자는 거의 쓰지 않는다. 모서리는 작게 둥글린다. 여백을 넉넉히 둔다.
- **표현**: 과장된 문구와 느낌표를 쓰지 않는다. 결과 카드는 "이유 → 스펙 → 가격·승인" 순서로 근거가 먼저 보이게 한다.
- **그림**: 제품 사진은 쓰지 않는다(저작권). 형태 4가지는 단순한 선 그림으로 직접 그린다.
- **다크 모드**: MVP에서는 밝은 화면만 만든다. 색은 CSS 변수로 두어 나중에 추가할 수 있게 한다.
