# 패들핏 — 외부 AI(GPT) 협업 브리프 (2026-11-17 기준)

이 문서는 GPT에게 디자인 시안·기획 검토를 부탁할 때 **함께 주는 맥락**이다. 코드와 결정의 기준은 이 저장소 하나이고, 여기 적힌 규칙과 결정을 지키는 제안만 반영한다. 최신 상태는 저장소의 `docs/decisions.md`, `docs/plan/m2.5-redesign.md`가 우선한다.

## 1. 서비스 한 줄
질문 6~7개에 답하면 **스펙 근거로** 맞는 피클볼 패들 3개를 이유·주의점과 함께 추천하고, 판매처로 연결하는 한국어 웹앱. 이름 "패들핏"(영문 표기는 상표 확인 전이라 쓰지 않음).

- 사이트: https://pickleball-paddle-ai.paddlefit.workers.dev (Next.js 16 정적 내보내기, Tailwind 4, Cloudflare Workers 정적 파일, **서버 코드·DB·로그인 없음**)
- 화면: 시작 `/` · 질문 `/quiz` · 결과 `/result` · 둘러보기 `/browse` · 공유받은 결과 `/shared?p=id,id,id` · 404
- 진행: M1(실사용판)·M2(상세·둘러보기·공유·다크 모드) 완료 → **지금 M2.5 리디자인 기획 단계**(`docs/plan/m2.5-redesign.md`, 카드 T-039~T-053) → 다음 M3(쿠팡 파트너스·사용 측정·피드백)

## 2. 반드시 지킬 규칙 (위반하는 제안은 반영하지 않는다)
1. **추천 순위는 구매 링크·수수료·제휴 여부와 무관**하다. 엔진은 스펙만 읽는다
2. **제품 값은 사람이 출처를 확인한 것만** 넣는다. 스펙·평가값을 추정하거나 만들어 넣지 않는다. 제품마다 출처 URL과 확인일이 있다
3. **제휴 링크에는 대가 표시**: 화면 첫 부분, 제목보다 앞, 본문과 구분, 접힌 영역·다른 페이지로 미루지 않음, 링크와 분리하지 않음. 쿠팡은 파트너스 권장 문구 그대로(공정위 추천·보증 심사지침)
4. **LLM·AI를 호출하지 않는다.** 추천 이유는 규칙별 문장 틀로 만든다. 그래서 화면에 **"AI 추천·AI 분석" 같은 표현을 쓰지 않는다**
5. **의학적 효과를 단정하지 않는다.** 팔 불편 답은 "불편을 줄이는 데 도움이 될 수 있는 사양"으로만 표현. 팔 불편 답은 건강 관련 정보라 **주소·공유 링크·저장 결과에 넣지 않는다**
6. 비밀값은 저장소에 두지 않는다

화면 원칙: 점수 숫자(예: "95% 적합")를 보여 주지 않고 라벨(매우 잘 맞음/잘 맞음/보통)로만. 회원가입 없음. 움직임은 transform·opacity만, "동작 줄이기" 설정 존중. 글자 대비 4.5:1 이상(밝은·어두운 화면 모두). 기준 폭 375px(최소 360px)부터 데스크톱까지.

## 3. 이미 정한 것 (다시 제안하지 말 것)
| 주제 | 결정 |
|---|---|
| 이미지 | 제조사 제품 사진 쓰지 않음. 패들은 직접 그린 형태 그림. 히어로·배경만 상업 이용 가능한 스톡 사진(사용자가 구입) |
| 플레이 밸런스 레이더, 제품별 컨트롤·파워·스핀·안정성·기동성 막대 | **출처 있는 특성 데이터를 확보한 뒤에.** 그 전에는 넣지 않는다(지금 데이터에 없는 값) |
| 색 | 코트 틸(주 버튼, `#0F6E56`) + 라임은 강조 배경으로만(라임 위 글자는 짙은 색, 라임 글자 금지) |
| 실시간 최저가 | 하지 않음. 네이버 쇼핑 검색 API는 2026-07-31 종료로 보임. 판매처 가격(사람이 30일마다 재확인) + "다른 곳 가격 비교"(네이버 쇼핑 검색 링크) |
| 공유 | 결과만 공유. 링크에는 제품 id만(답변 없음). 카카오 SDK 없이 링크 복사 + 휴대폰 기본 공유 창 |
| 화면 구조 | 리포트형 기본(1순위 크게, 2·3순위 한 줄, 바텀시트). 둘러보기·필터·비교는 앱형 |
| 하지 않는 것 | 회원 기능, 리뷰·커뮤니티, 가격 자동 수집, LLM 호출, 제조사 사진 |

## 4. 지금 데이터 (화면 시안에 쓸 수 있는 것)
- 제품 23개, 브랜드 13개(JOOLA 5, Franklin 3, NOX·Six Zero·Friday·11SIX24 각 2, 그 밖 1개씩). 가격 29,900~519,000원. 형태: 길쭉한 형 9, 하이브리드형 8, 넓은 형 4, 표준형 2
- 제품 필드: `id, brand, model, weight_oz, core_mm, shape(standard·hybrid·elongated·widebody), length_in, width_in, surface(carbon·fiberglass·composite·other), price_krw, price_checked_at, certification(usa_pickleball: approved·not_approved·unknown + checked_at), sources(출처 URL), verified_at, purchase(url, is_affiliate)`
- **없는 값**: 사진, 스핀·안정성·기동성 같은 평가값, 코어 소재, 그립 두께, 재고. 시안에 넣으면 "데이터 없음"이다
- 질문(7개, 입문자는 형태 질문 빼고 6개): 경력, 플레이 성향(컨트롤·균형·파워·모르겠음), 무게 선호, 팔 불편, 선호 형태(여러 개), 예산(10만 이하·10~20만·20~30만·상관없음), 대회 승인 필요
- 추천 결과마다: 적합도 라벨, 이유 문장 몇 개, 주의점 몇 개(규칙 문장)

## 5. GPT에게 부탁하는 일 / 부탁하지 않는 일
| 부탁함 | 부탁하지 않음 |
|---|---|
| 화면 시안 이미지·와이어프레임(위 4장의 필드만 사용) | 코드 구현 결과를 그대로 반영(테스트·빌드 검증은 저장소에서) |
| 기획 비평·대안(이 브리프의 규칙 안에서) | 제품 스펙·가격·승인 값 조사 결과를 사실로 쓰기(원문 확인 필요) |
| 문구 후보 여러 개(과장·"AI" 없이) | 이미 정한 것(3장) 뒤집는 제안 — 필요하면 "결정 변경 제안"으로 따로 표시 |

## 6. 결과물 형식 (돌려줄 때)
- 시안 그림에는 **실제 데이터의 제품명·값만** 쓰거나, 가짜 값이면 "예시"라고 그림 안에 표시
- 제안마다: 대상 화면, 바꾸는 이유, 위 2·3장 규칙과 부딪히는지 스스로 점검한 결과
- 확인하지 못한 사실은 "미확인"으로 표시

## 7. 부탁할 때 쓸 문장 예시
> 첨부한 브리프(gpt-brief.md)와 소스 ZIP을 기준으로, **결과 화면 데스크톱(1440px) 시안을 2안** 만들어 줘. 브리프 2장 규칙(점수 숫자 없음, AI 표현 없음, 대가 표시는 제목 앞)과 3장 결정(레이더·특성 막대 없음, 제조사 사진 없음)을 지키고, 4장 필드만 써. 각 안마다 바꾼 점과 규칙 점검 결과를 표로 붙여 줘.

> 이 브리프 기준으로 `docs/plan/m2.5-redesign.md`를 비평해 줘. 빠진 사용자 관점, 우선순위가 이상한 카드, 더 단순하게 할 수 있는 부분을 근거와 함께. 규칙을 바꿔야 하는 제안은 "결정 변경 제안"으로 따로 모아 줘.
