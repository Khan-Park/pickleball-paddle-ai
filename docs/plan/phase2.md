# 2단계 기획안: 실사용판 (v0.2, 2026-11-16 결정 반영)

1단계(MVP)는 "질문 → 추천 3개"가 맞게 나오는지 확인하는 단계였다. 2단계의 목표는 **실제로 패들을 고르고 사러 가는 데 쓰이는 앱**이다. 이 문서는 범위, 모바일 화면, 로딩·전환 연출, 디자인 고도화, 작업 순서를 정한다. 코드는 없다.

관련 문서: [docs/spec.md](../spec.md), [docs/design/ui-flow.md](../design/ui-flow.md), [docs/deploy.md](../deploy.md), [docs/decisions.md](../decisions.md)

---

## 1. 목표와 실사용 기준

**한 줄 목표**: 입문자도 3분 안에 "나에게 맞는 패들 1개"를 근거와 함께 고르고, 판매처로 이동할 수 있다.

**실사용 기준(2단계 완료 조건)**
1. 결과의 모든 제품에 구매하러 갈 수 있는 링크가 있다.
2. 추천 3개를 한 화면에서 비교할 수 있다.
3. 질문에 나오는 모든 선택지에 맞는 제품이 데이터에 1개 이상 있다(지금은 표준형 0개).
4. 화면 전환과 기다림에 시각적 피드백이 있고, 휴대폰에서 끊김 없이 동작한다.
5. 가격·스펙·승인 정보가 기준일 안에 있다(`check:release` 통과 상태 유지).

**측정할 지표(측정 도구는 M3에서 결정)**: 시작 → 결과 도달률, 결과 → 판매처 이동률, 비교·상세 열람률.

## 2. 현재 상태와 부족한 점 (2026-11-16 기준)

| 영역 | 현재 | 부족한 점 |
|---|---|---|
| 데이터 | 20개. 길쭉한 형 9, 하이브리드 7, 넓은 형 4, **표준형 0**. 대회 승인 15, 미확인 5. 가격 29,900~519,000원 | 표준형이 없어 질문 선택지와 맞지 않는다. 가격 확인일이 2026-11-15라 **12월 15일쯤 `check:release`가 실패**한다 |
| 구매 | 링크 없음. 대가 표시 틀(D-022·D-023)은 완성 | 결과에서 다음 행동이 없다 |
| 결과 화면 | 카드 3개, 이유·주의·스펙·가격·승인 | 카드가 길어 3개를 비교하기 어렵다. 스펙 숫자의 의미를 알기 어렵다 |
| 화면 연출 | 질문이 바뀔 때 포커스만 이동. 애니메이션 없음 | 화면이 툭툭 바뀌어 앱처럼 느껴지지 않는다. 결과가 너무 갑자기 나와 "계산했다"는 느낌이 약하다 |
| 디자인 | 남색·회색 톤, 시스템 글꼴, 직접 그린 형태 그림 | 위계(무엇이 중요한지)가 약하고 브랜드 느낌이 없다 |
| 공유·재방문 | 없음(sessionStorage만) | 동호회에 결과를 보여 줄 방법이 없다 |

## 3. 사용자와 사용 장면

| 사용자 | 장면 | 2단계에서 필요한 것 |
|---|---|---|
| 입문자(가장 많음) | 동호회 가입 후 첫 패들을 사려 한다. 용어를 모른다 | 용어 도움말, "왜 이 제품인지" 한 줄 요약, 가격대별 선택 |

## 4. 범위와 우선순위

마일스톤 3개로 나눈다. **M1을 마치면 실사용 기준 1~5를 만족한다.**

### M1. 실사용 최소판 (P0)
| 기능 | 내용 | 수용 기준(요약) |
|---|---|---|
| 판매처 링크(일반) + 가격 비교 연결 | "판매처에서 보기"(지금 출처로 쓰는 국내 판매처 1곳) + "다른 곳 가격 비교"(가격 비교 사이트 검색 결과로 이동). 둘 다 제휴가 아니므로 대가 표시 없음(8.1) | 20개 모두 두 링크. 새 탭으로 열리고 `rel="noopener noreferrer"`. 판매처 링크 주소가 출처와 같은지 데이터 점검 |
| 추천 비교표 | 결과 상단 "3개 비교하기" → 바텀시트에 표(무게·코어·형태·크기·가격·승인·핵심 이유) | 375px에서 가로 스크롤 없이 3열이 보인다. 다른 값만 강조 |
| 스펙 시각화 | 무게·코어 두께를 "가벼움 ↔ 묵직함", "파워 ↔ 컨트롤" 막대 위 점으로 표시 | 숫자와 함께 표시(색만으로 구분하지 않음) |
| 용어 도움말 | 코어 두께, 형태, 무게, 대회 승인에 ⓘ 버튼 → 짧은 설명 시트 | 질문·결과 화면 어디서든 같은 설명 |
| 로딩·전환 연출 | 5장 설계 전체 | 6장의 접근성·성능 조건 충족 |
| 디자인 고도화 1차 | 7장의 디자인 토큰, 결과 카드 재설계, 시작 화면 개편 | 7장 체크리스트 |
| 데이터 보강 | 표준형 제품 2개 이상 추가, 가격 재확인 절차 문서화, 조합별 제품 수 보고(9장) | 모든 질문 선택지에 맞는 제품 존재. 가격 확인일 30일 이내 |

### M3. 수익과 개선 (P2)
| 기능 | 내용 |
|---|---|
| 쿠팡 파트너스 | 가입·활동 페이지 등록 후 제휴 링크. 대가 표시는 이미 구현된 D-022 방식 그대로 |
| 사용 측정 | 쿠키 없는 방식 우선 검토(Cloudflare Web Analytics 등, 조건 미확인). 개인정보 안내 문구와 함께 |

## 5. 모바일 화면 설계 (기준 폭 375px, 최소 360px)

화면은 "한 손, 엄지 영역"을 기준으로 한다. 주요 버튼은 화면 아래쪽, 높이 48px 이상.

### 5.1 시작 `/`
```
┌──────────────────────────┐
│ [로고] 패들 추천           │ ← 상단 바(고정 아님)
│                          │
│  질문 1분, 나에게 맞는     │ ← 제목 28px
│  패들 3개                 │
│  스펙 근거로 이유와 함께    │
│                          │
│  [형태 그림 4개가 천천히    │ ← 장식 일러스트(5.1-a)
│   번갈아 강조되는 영역]     │
│                          │
│  ✓ 스펙 근거  ✓ 수수료 무관 │ ← 신뢰 요소 3개를 칩으로
│  ✓ 대회 승인 확인          │
│                          │
│ ┌──────────────────────┐ │
│ │     질문 시작하기       │ │ ← 하단 고정 버튼
│ └──────────────────────┘ │
└──────────────────────────┘
```
- 5.1-a: 형태 그림 4개(지금의 `ShapeIcon`)를 크게 그리고 2초 간격으로 하나씩 강조한다. 움직임 줄이기 설정이면 정지.
- "둘러보기" 링크는 M2에서 버튼 아래에 추가.

### 5.2 질문 `/quiz`
```
┌──────────────────────────┐
│ ←   ●●●○○○○        3/7   │ ← 진행 막대(점 또는 막대)
│                          │
│ 패들 무게는 어떤 쪽이       │ ← 질문 22px
│ 좋나요?  ⓘ               │ ← 용어 도움말
│                          │
│ ┌──────────────────────┐ │
│ │ 가볍게                 │ │ ← 선택지 카드(높이 64px 이상)
│ │ 빠르게 다루기 쉬움       │ │
│ └──────────────────────┘ │
│ ┌──────────────────────┐ │
│ │ ✓ 중간                │ │ ← 선택됨: 테두리+배경+체크
│ └──────────────────────┘ │
│  ...                     │
│                          │
│        처음부터 다시 답하기 │
└──────────────────────────┘
```
- 답을 누르면 선택 표시가 먼저 보이고(150ms) 다음 질문으로 넘어간다(6.2).
- 형태 질문(여러 개 선택)만 하단 고정 "다음" 버튼.

### 5.3 분석 중 (전환 화면, 새로 추가)
```
┌──────────────────────────┐
│                          │
│      [패들 아이콘이         │
│       공을 치는 루프]       │
│                          │
│   ✓ 조건 확인              │ ← 단계 문구가 차례로 체크
│   ● 20개 패들 스펙 비교     │
│   ○ 추천 3개 정리          │
│                          │
│        건너뛰기 →          │
└──────────────────────────┘
```
- 마지막 질문 답 → 이 화면 → 결과. 6.3의 시간 규칙을 따른다.
- 문구의 숫자(20개)는 실제 데이터 개수로 채운다(꾸민 숫자를 쓰지 않는다).

### 5.4 결과 `/result`
```
┌──────────────────────────┐
│ [광고 안내 — 제휴 링크가    │ ← 제휴 링크가 있을 때만(D-022)
│  있을 때만, 제목보다 위]    │
│ 내 조건 요약: 입문·균형·…   │ ← 칩. 누르면 답변 고치기
│                          │
│ 맞는 패들 3개    [비교하기] │
│                          │
│ ┌ 1순위 ───────────────┐ │
│ │ 브랜드  모델명          │ │
│ │ ■■■■□ 매우 잘 맞음      │ │ ← 적합도 막대(점수 숫자는 숨김)
│ │ "가볍고 컨트롤이 쉬운…"  │ │ ← 핵심 이유 1줄
│ │ [7.9oz][16mm][넓은 형]  │ │ ← 스펙 칩
│ │ 약 199,000원 · ✓승인    │ │
│ │ [판매처에서 보기 ↗]      │ │
│ │ 자세히 ▾               │ │ ← 이유 전체·주의·스펙 막대 펼치기
│ └──────────────────────┘ │
│ 2 · 브랜드 모델 · 잘 맞음 ›│ ← 2·3순위는 한 줄 행(7.2)
│ 3 · 브랜드 모델 · 보통   ›│   누르면 상세 시트
│                          │
│ 그립 고르는 법 ▸ · 용어 ▸  │
│ 안내 문구(스펙 기준, 수수료 무관)│
│                          │
│ [다시 해 보기] [공유(M2)]  │
└──────────────────────────┘
```
- 첫 화면(스크롤 전)에 1순위 카드의 이름·적합도·핵심 이유·가격·구매 버튼이 모두 보여야 한다.
- 결과가 3개보다 적거나 0개일 때의 문구와 조건 완화 버튼은 지금 동작을 유지하고 스타일만 새로 맞춘다.

### 5.5 바텀시트 (비교·도움말·상세)
- 아래에서 올라오는 시트. 손잡이 표시, 바깥 누르기·아래로 끌기·닫기 버튼으로 닫는다.
- 시트가 열리면 포커스를 시트 안으로, 닫히면 연 버튼으로 돌려준다. 배경 스크롤을 막는다.

## 6. 로딩·전환 연출 설계

### 6.1 원칙
- 이 앱은 정적 사이트이고 추천 계산이 즉시 끝난다. 그래서 연출의 목적은 **기다림을 가리는 것이 아니라, 무엇이 바뀌었는지 알려 주고 "근거를 계산했다"는 신뢰를 주는 것**이다.
- **인위적인 대기는 한 곳(5.3 분석 중)만** 둔다. 그 외에는 모든 연출이 사용자 조작을 늦추지 않는다(애니메이션 중에도 다음 입력 가능).
- 움직임은 `transform`과 `opacity`만 쓴다(휴대폰에서 끊기지 않게). 새 애니메이션 패키지 없이 CSS로 만든다. 필요해지면 그때 이유를 적고 승인을 받는다.
- 운영체제의 "동작 줄이기"(`prefers-reduced-motion: reduce`)를 켠 사용자에게는 이동·확대 연출을 끄고 짧은 페이드만 남긴다. 5.3 분석 중 화면은 건너뛴다.

### 6.2 연출 목록
| 위치 | 연출 | 시간·곡선(초안) |
|---|---|---|
| 모든 버튼 | 누르는 순간 살짝 작아짐(98%) | 100ms |
| 선택지 선택 | 테두리·배경색 전환 + 체크 표시 등장 → 다음 질문으로 | 150ms 표시 후 넘어감 |
| 질문 전환 | 앞으로: 새 질문이 오른쪽에서 밀려 들어옴 + 페이드. 뒤로: 반대 방향 | 220ms, ease-out |
| 진행 막대 | 길이가 부드럽게 늘어남 | 300ms |
| 시작 화면 | 형태 그림 순차 강조(5.1-a), 제목·버튼 순차 등장 | 등장 400ms, 강조 2초 간격 |
| 분석 중(5.3) | 6.3 참고 | 최대 1.2초 |
| 결과 카드 | 1→2→3순위 순서로 아래에서 떠오르며 등장 | 카드당 280ms, 80ms 간격 |
| 적합도 막대 | 0에서 채워짐 | 500ms, 카드 등장 후 |
| 카드 "자세히" | 높이 펼침 + 내용 페이드 | 200ms |
| 바텀시트 | 아래에서 올라옴 + 배경 어두워짐 | 250ms |
| 결과 화면 첫 표시 | 저장된 답을 읽기 전 잠깐 빈 화면 대신 **카드 모양 스켈레톤**(회색 상자가 은은하게 깜빡임) | 읽는 즉시 교체 |
| 판매처 이동 | 버튼 누르면 "판매처로 이동합니다" 짧은 안내(새 탭) | 1초 이내 사라짐 |

### 6.3 분석 중 화면의 시간 규칙
- 전체 0.9~1.2초. 단계 문구 3개를 약 350ms 간격으로 체크한다.
- 화면 아무 곳이나 누르거나 "건너뛰기"를 누르면 바로 결과로 간다.
- "답변 고치기"로 돌아갔다가 다시 결과를 볼 때는 짧게(0.5초) 하거나 생략한다(반복 대기 방지).
- **넣는다** (사용자 확정 2026-11-16). 근거는 "결과가 바로 뜨면 계산 없이 정해진 답처럼 느껴진다"는 가정이며 검증된 것은 아니다. 측정(M3) 후 유지 여부를 다시 본다. 동작 줄이기 설정이면 보여 주지 않는다(6.1).

### 6.4 구현 메모 (확인 필요)
- Next 16의 화면 전환 기능(View Transitions 연동)을 쓸 수 있는지는 `node_modules/next/dist/docs/`에서 확인한 뒤 정한다. 쓸 수 없으면 질문 전환은 같은 페이지 안의 상태 전환이라 CSS만으로 충분하다.
- 분석 중 화면은 별도 주소가 아니라 결과 화면의 첫 상태로 만든다(새로고침 시 다시 보여 주지 않도록 탭 저장소에 표시).

## 7. 디자인 고도화

### 7.1 결정 순서
디자인은 **구조 → 컴포넌트 → 시각 요소(색·글꼴)** 순서로 정한다. 색은 구조가 정해진 뒤 같은 화면에서 비교한다.

### 7.2 화면 구조: "리포트형" 기본 + "앱형 탐색" 일부 (사용자 확정 2026-11-16)
두 방향을 시안으로 비교한 뒤 정했다.

| 축 | 채택 | 이유 |
|---|---|---|
| 이동 방식 | 탭바 없이 한 흐름(시작 → 질문 → 분석 중 → 결과). 상단은 진행 막대와 뒤로 | 제품 20개 규모에 탭바는 과하다. 입문자가 길을 잃지 않는다 |
| 질문 입력 | 세로 선택지 카드(제목 + 설명 한 줄) | 입문자에게 설명 한 줄이 필요하다. 2열 아이콘 타일은 설명 자리가 없다 |
| 진행 표시 | 이어진 막대 + "3/7" | |
| 결과 표현 | 1순위를 크게(적합도 막대·핵심 이유·스펙 칩·가격·승인), 2·3순위는 한 줄 행. 누르면 상세 시트 | 가로 스와이프 카드는 2·3순위를 덜 보게 하고 비교가 어렵다 |
| 주요 행동 | 하단 고정 주 버튼 1개("판매처에서 보기", 지금 보고 있는 제품 기준) | 엄지 영역. 한 화면에 주 버튼은 하나 |
| 비교·상세·도움말 | 아래에서 올라오는 바텀시트 | 흐름을 벗어나지 않는다 |
| 내 조건 | 결과 상단 칩. 누르면 답변 고치기 | |
| B에서 가져올 것 | 필터 칩과 목록(둘러보기, M2), 비교함 개념(둘러보기를 넣을 때) | 탭바는 M2에서 둘러보기가 생길 때 다시 판단 |

### 7.3 방향과 강조색
"**차분한 신뢰 + 코트의 활력**". 1단계의 남색·회색 톤(ui-flow 10장)을 유지하고 강조색 하나를 둔다. 과장 문구, 느낌표, 번쩍이는 효과는 계속 쓰지 않는다.

**강조색: 코트 청록 (사용자 확정 2026-11-16)**. 7.2 구조의 같은 결과 화면에 파랑 유지·코트 청록·공 연두를 칠해 비교한 뒤 정했다. 남색 기본 톤과 어울리고 흰 글자 버튼이 잘 읽힌다.
- 쓰임: 적합도 막대, 선택 표시, 진행 막대, 주 버튼, 선택된 칩
- 시안 값(구현 때 명도 대비를 계산해 조정): 막대·선 `#1D9E75`, 주 버튼 바탕 `#0F6E56`(흰 글자), 옅은 바탕 `#E1F5EE`, 옅은 바탕 위 글자 `#085041`
- 대회 승인 확인의 초록(`#15803D`)과 헷갈리지 않게 승인 표시는 아이콘·글자를 함께 쓰고, 구현 때 두 색을 나란히 놓고 구분되는지 확인한다
- 지금의 파랑 `#2F6FED`는 링크·정보 표시용으로만 남길지 구현 때 정한다

## 8. 구매 링크 설계

### 8.1 1차: 일반 판매처 링크 (M1)
- 데이터 `purchase: { url, is_affiliate: false }`. 스키마는 이미 있다(D-023). 제휴가 아니므로 `program`은 넣지 않고 대가 표시도 나오지 않는다(규칙 3).
- 지금 20개 모두 국내 판매처(피앤피노) 상품 페이지가 출처에 있다. 링크로 쓰기 전에 **판매 중인지, 같은 옵션인지** 사람이 확인한다(규칙 2).
- 버튼 문구: "판매처에서 보기 ↗". 가격 옆에 "판매처 가격과 다를 수 있음" 유지.
- **판매처 1곳 + 가격 비교 사이트 연결** (사용자 확정 2026-11-16). 사람이 확인한 판매처 1곳의 가격과 링크를 보여 주고, "다른 곳 가격 비교" 버튼으로 가격 비교 사이트(다나와·네이버 쇼핑 등)의 해당 모델 검색 결과로 보낸다. 스키마의 `purchase`는 그대로 두고, 비교 링크용 필드는 T-019에서 정한다.
- 사람이 여러 판매처 가격을 손으로 갱신하는 방식은 쓰지 않는다. 판매처가 늘수록 틀린 최저가를 보여 줄 위험이 크다.
- 앱 안 실시간 최저가는 M2에서 쇼핑 검색 API로 검토한다(4장 M2 표).
- **확인 필요**: 판매처 상품 페이지와 가격 비교 사이트 검색 결과로 바로 링크하는 것에 이용약관상 문제가 없는지, 가격 비교 사이트의 검색 주소 형식.

### 8.2 2차: 쿠팡 파트너스 (M3)
선행 조건:
1. Cloudflare 무료 요금제의 상업 이용 조건 확인(약관 원문 미확인)
2. 쿠팡 파트너스 가입, 활동 페이지 등록. workers.dev 주소로 가능한지, 도메인이 필요한지 미확인
3. 이용약관·운영정책 전문 확인(활동 금지 사항)
4. 제품별 쿠팡 판매 여부와 같은 모델인지 확인
5. 대가 표시는 D-022 방식(제목보다 위 안내 + 링크 바로 위 권장 문구)을 그대로 쓴다. 이미 구현·테스트됨
