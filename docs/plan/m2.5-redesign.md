## 0. 요약
- **권고안**: 시안의 화면 구조와 색(코트 틸 + 라임 포인트)은 받아들이고, 시안 속 내용 중 근거가 없는 것(AI 표현, 실제 브랜드명·수치, 레이더·특성 막대, 점수 같은 강조 배지)은 **우리 데이터로 대체하거나 자리만 남긴다**. 구현은 토큰 → 공통 부품 → 화면 → P1 기능 순서로 카드 14개(T-039~T-052)로 나눈다.
- **먼저 정할 것**(8장 상세): (U1) 주 버튼 색은 틸 유지(제안) / 시안 모바일처럼 라임, (U2) 저장 보관 기간 180일 자동 삭제(제안) / 사용자가 지울 때까지, (U3) 헤더 "추천 가이드" 메뉴는 빼기(제안) / 가이드 화면 신설, (U4) 무게 g 병기(제안) / oz만, (U5) 질문 선택지 사진 쓰지 않음(제안) / 스톡 사진 추가 구입.
- **원칙 충돌은 모두 시안을 바꾸는 쪽으로 처리했다**(3장). 기존 결정을 바꾸는 항목은 없다.
- 이 문서에서 Next 16 기능은 두 가지만 전제한다. 정적 내보내기에서 `next/image` 기본 최적화를 쓸 수 없다는 점(`node_modules/next/dist/docs/01-app/02-guides/static-exports.md` "Unsupported Features" 확인함), 라우트 그룹 동작(`.../03-file-conventions/route-groups.md` 확인함, 쓰지 않는 쪽을 권고). Tailwind 4 기본 브레이크포인트 값은 `node_modules/tailwindcss/theme.css`에서 확인했다.

| 제품(카드·비교·상세·예시) | **직접 그린 패들 그림**. 형태 4종(표준·넓은·하이브리드·길쭉한)별 SVG, 크기 3단계. 실제 제조사 무늬·로고를 흉내 내지 않는다(상표 오인 방지). 제품별 색 구분이 필요하면 토큰 안 색 몇 개를 id로 고정 배정 | 지금 `ShapeIcon`을 다듬어 바로 씀(대체가 아니라 최종본) |
| 홈 히어로·결과 히어로·모바일 홈 배경 | 사용자가 상업 이용 가능한 스톡을 골라 구입. **브랜드 로고가 보이는 사진은 고르지 않는다** | 짙은 네이비→틸 그라데이션 + 코트 선 SVG 무늬 + 패들 그림·공 그림. 사진 자리를 부품(`HeroMedia`)으로 두고 파일 경로만 바꾸면 교체되게 |
| 질문 선택지 | U5. 제안: 사진 없음, 아이콘·형태 그림 | — |
- 정적 내보내기라 `next/image` 기본 최적화를 쓸 수 없다(문서 확인함). 사진은 빌드 전에 사람이 크기별(예: 모바일·데스크톱 2종) WebP로 만들어 `public/`에 두고 `<img>`(또는 `unoptimized`)로 쓴다. 폭·높이를 적어 CLS를 막는다. 파일 용량 상한은 첫 측정 후 정한다(미확인).
- 사진 위 글자: 사진 대비는 테스트로 계산할 수 없다. 사진 위에 히어로 바탕색 덮개(불투명도 토큰)를 깔고, 덮개 색 위에서 대비를 계산한다. 실제 사진에서는 가장 밝은 부분 위 글자를 사람이 확인한다.
- 라이선스 기록: 구입 사진마다 출처·라이선스 종류·구입일·허용 범위(웹·상업·수정)를 남긴다(위치는 T-041에서 `docs/design/assets.md` 제안). 라이선스 해석은 법률 판단이므로 **약관 원문 확인은 사용자, 애매하면 전문가 확인**.

### 3.4 레이더·특성 막대 (D-035 (3), 핵심 규칙 2)
데이터 확보 전까지 그 자리는 이렇게 둔다.
| 시안 자리 | 대체 |
|---|---|
| 결과 왼쪽 "내 플레이 밸런스" 레이더 | (D-037: 왼쪽 열 없음) 히어로 아래 **가로 조건 칩 줄**(팔 불편 제외) + 옆의 "추천 기준 보기" 버튼이 바텀시트(데스크톱은 대화상자)로 **"추천에 반영한 조건"** 목록을 연다: 답변 칩(팔 불편 제외) + 그 답이 어떤 스펙 기준이 됐는지 한 줄씩(예: "중간 무게 → 7.3~8.4oz를 우선", 값은 `scoring-config.ts`의 기존 상수에서 읽음, 새 수치 만들지 않음). 점수 가중치 숫자는 보여 주지 않는다 |
| 카드·비교표의 컨트롤·파워·스핀·안정성·기동성 막대 | 기존 `SpecScale`(무게·코어 두께를 범위 위 점으로) — 실제 스펙이라 근거가 있다 |
| 비교표 "플레이 특성 비교" 탭 | 탭 없이 "주요 스펙 비교"만 |
- 특성 데이터 확보는 6장(조사 카드 T-052). 확보되면 레이더·막대를 별도 카드로.

### 3.5 점수 숫자 비노출
- 적합도는 라벨 3단계 + 막대(지금 `FitBar`, 너비만 점수 비례)로만. 시안의 "가장 추천" 배지는 "1순위"로, 2·3순위 특성 배지는 쓰지 않는다.
- 저장·공유에도 점수를 담지 않는다(5.1).
- PDF의 "TOP3 다양성 규칙(적합형·대안형·예산형)"은 엔진 변경이라 이번 범위 밖(핵심 규칙 1 영향 검토 필요, M3 이후 후보).

### 3.6 대가 표시(D-022) 위치
- **원칙**: 대가 표시는 "게시물의 첫 부분"에 둔다. 공통 헤더(사이트 메뉴)는 게시물이 아니므로 헤더 **바로 아래, 히어로·`h1`보다 앞**에 전체 폭으로 둔다. 헤더 안에 넣지 않는다(작아지고 메뉴와 섞임).
- 결과 화면 데스크톱 순서(D-037): 헤더 → 대가 표시(전체 폭) → 히어로(`h1`) → 가로 조건 요약 줄 → 카드 3열(전체 폭) → 주요 스펙 비교 표 → 하단 행동 줄. 대가 표시를 조건 줄이나 카드 열 안에 넣지 않는다.
- CSS로 시각 순서를 바꾸지 않는다: 대가 표시 묶음과 그 부모에 `order-*`, `absolute`, `fixed`, `sticky`, `hidden lg:block` 류를 쓰지 않는다(완료 기준 5의 검사).
- 카드 3열(데스크톱): 카드마다 이름 근처 "광고" 배지 + 구매 링크 바로 위 표시 문구 묶음(지금 `BuyButtons`·`PurchaseLink` 그대로). 카드를 세로로 줄이려고 구매 묶음을 접힘(`details`) 안에 넣지 않는다.
- 하단 고정 구매 바(`StickyBuy`)는 모바일 전용으로 두고, 1024px 이상에서는 숨긴다(카드에 구매 묶음이 보이므로). 숨기는 경우에도 표시 묶음은 함께 숨는 구조라 분리되지 않는다.
- 히어로 바탕(짙은 색)에는 대가 표시를 올리지 않는다(지금 표시 색 토큰이 밝은 바탕 기준).
- 지금 제휴 링크 0개라 실제 노출은 M3부터. 그래도 이번 카드에서 위치·테스트를 맞춘다.
- 남은 문제(m2.md 10장 B)는 그대로 M3 T-029의 선행 조건.

### 3.7 명도 대비와 라임 규칙
- 라임 위 글자는 **고정 짙은 색 `--on-lime`만**. 흰 글자 금지.
- 라임을 **글자색으로 쓰지 않는다**(흰·밝은 바탕에서 약 1.2:1로 예상, 계산은 테스트가 함). 결과 히어로의 "3가지" 강조도 라임 글자 대신 흰 글자 + 라임 밑줄 띠.
- 라임만으로 뜻을 전하지 않는다(선택 상태·진행·적합도는 틸 + 아이콘·글자). 라임은 강조 띠, 1순위 배지 바탕, 히어로 꾸밈, 공 그림에만.
- 포커스 링: 밝은 바탕은 지금처럼 틸, 짙은 히어로 위에서는 `--focus-on-hero`(라임 또는 흰색, 3:1 이상).

## 5. P1 기능 범위 (D-035)

### 5.1 로컬 결과 저장 (로그인 없음)
| 항목 | 방침(안) |
|---|---|
| 저장소 | `localStorage`, 키 `pb.saved.v1`. 서버·주소로 보내지 않는다 |
| 저장 내용(한 건) | `id`(무작위 문자열), `saved_at`(날짜), `paddle_ids`(최대 3, 순위 순), `conditions`(화면용 조건 칩 문구 — 지금 `conditionChips`와 같은 규칙이라 **팔 불편 제외**), `relaxed`(조건 완화 결과 여부), `scoring_version` |
| 저장하지 않는 것 | 팔 불편 답, 질문 답 원문, 점수·라벨·이유 문장(데이터·엔진이 바뀌면 틀린 말이 됨), 구매 링크 |
| 다시 볼 때 | 지금 데이터로 그 제품들을 공유받은 화면과 같은 모양으로 보여 줌. 없어진 제품은 "지금은 목록에 없음"(T-025 처리 재사용). "저장 당시 추천이며 가격·스펙은 오늘 기준"이라고 적음. 적합도 라벨은 없음(답을 저장하지 않으므로) |
| 개수 | 최대 10건. 넘으면 가장 오래된 것부터 지우고 알림 |
| 보관 기간 | U2: 180일 자동 삭제(제안, 데이터 재확인 주기와 같음) / 사용자가 지울 때까지 |
| 화면 | `/saved`: 목록(날짜·조건 칩·제품 3개 이름), 하나씩 지우기, 모두 지우기. "이 기기 브라우저에만 저장되며, 브라우저 데이터를 지우면 사라집니다" 안내. 결과 화면의 "결과 저장" 버튼(저장 후 토스트 + 저장 화면 링크). 헤더 책갈피 아이콘 → `/saved` |
| 같은 결과 중복 | 같은 `paddle_ids`·`conditions`면 새로 만들지 않고 날짜만 갱신 |
| 저장소가 막힌 환경 | 사생활 모드 등에서 쓰기 실패 → 버튼에 "이 브라우저에서는 저장할 수 없습니다" 안내, 화면은 계속 동작(지금 storage.ts 방식) |
| 개인정보 | 기기 안에만 있고 식별 정보가 없다. 다만 공용 기기에서 다른 사람이 볼 수 있으므로 팔 불편 답은 넣지 않는다. 로컬 저장만으로 개인정보 처리방침·안내 의무가 생기는지는 **미확인 — 전문가 확인 필요**(M3 T-030 개인정보 안내 때 함께) |
- 시안의 "관심 제품 저장(제품 하나씩 책갈피)"은 D-035 범위(결과 저장)에 없어 **이번에는 하지 않는다**.

### 5.2 브랜드·무게 필터와 검색 (둘러보기)
- 검색: 브랜드 + 모델 이름의 부분 일치, 대소문자·공백 무시. 화면 안 상태로만(주소·저장소에 남기지 않음 — 지금 필터 원칙). 헤더 검색 아이콘은 `/browse`로 가서 검색칸에 포커스(주소 해시 사용, 쿼리 문자열은 쓰지 않음).
  - 한글 브랜드 표기("줄라" 등) 검색은 데이터에 한글 이름이 없어 이번엔 안 됨(필요하면 데이터 필드 추가가 별도 결정).
- 브랜드: 데이터에서 목록을 만들어 칩(여러 개 선택). 지금 13개.
- 무게: 3구간 칩 — 가벼움(7.3oz 미만)·중간(7.3~8.4oz)·묵직함(8.4oz 초과). 경계값은 엔진의 `WEIGHT_BAND`를 **읽기만** 해서 퀴즈와 같은 기준을 쓴다(새 수치 없음). 경계 포함 규칙은 엔진 판정과 같게 테스트로 고정.
- 기존 형태·가격·승인 필터, 정렬(가격 낮은 순), "필터 지우기"와 함께 동작. 필터 묶음은 모바일에서 접힘 유지(T-037), 데스크톱은 왼쪽 열에 펼침.
- `filterAndSort`는 `PaddleSpec` 필드와 이름만 받는 원칙 유지.

### 5.3 둘러보기에서 비교 담기 (최대 3개)
- 목록 줄·카드마다 "비교 담기" 토글(누른 상태 `aria-pressed`). 3개가 차면 나머지 버튼은 누를 수 있되 "최대 3개까지 비교할 수 있습니다" 안내(비활성화로 숨기지 않음).
- 아래 고정 비교함: 담은 제품 이름(그림 작게) + "비교하기"(2개 이상일 때) + 비우기. 모바일 하단 고정, 데스크톱은 본문 하단 고정 띠.
- "비교하기"는 결과 화면과 **같은 비교 부품**(T-047에서 일반화)을 연다. 둘러보기 열은 적합도·핵심 이유 줄이 없다.
- 담은 목록은 `sessionStorage`(상세 시트·새로고침 사이 유지, 탭 닫으면 사라짐). 구매·제휴 정보는 담지 않고 id만.
- 결과 화면은 지금처럼 "추천 2~3개 모두 비교"를 유지한다(체크박스로 고르는 시안 방식은 3개뿐이라 이득이 작다).

## 6. 데이터 작업 제안: 특성 데이터(스핀·안정성 등)

- **카드 T-052(조사만)**: 컨트롤·파워·스핀·안정성·기동성 값을 출처 있게 얻을 수 있는지 조사한다. 수집·화면 반영은 조사 결과를 보고 사용자가 정한다. 외부 조사이므로 **fury 조사 필요**, 핵심 출처는 hawkeye 원문 대조(D-031 방식).
- 조사 대상(후보, 실제 존재·조건은 모두 미확인)
  1. 제조사가 공식 페이지에 적은 특성 표기(예: 자체 등급·막대). 브랜드마다 척도가 달라 서로 비교 가능한지
  2. 같은 장비로 여러 제품을 측정한 공개 측정치(스윙웨이트·트윈웨이트·RPM 등)를 내는 연구실·리뷰 매체. 측정 방법 공개 여부, 이용 조건(인용·상업 사이트 게재 허용)
  3. 측정 대신 스펙에서 계산(예: 무게·코어로 기동성 추정) — **핵심 규칙 2와 충돌 가능성이 높아** 쓸 경우 "추정·계산값"임을 화면에 밝혀야 한다. 기본은 제외 권고
- 출처 기준(제안)
  - 값마다 출처 URL·확인일·측정 방법(측정/제조사 자체 등급)을 남긴다(PDF의 SpecificationSource 구조와 같은 생각, 지금 `sources`·`verified_at` 확장).
  - 서로 다른 척도는 섞지 않는다. 한 척도로 23개 중 대부분을 덮지 못하면 레이더를 넣지 않는다(덮는 비율 기준은 조사 후 사용자 결정).
  - 이용 조건이 상업 사이트 게재를 허락하지 않으면 쓰지 않는다.
- 산출물: `docs/plan/t-052-research.md`(조사), 결정 후 데이터 스키마 변경 카드는 따로.

## 9. 위험과 미확인

### 위험
- **대가 표시 위치 회귀**: 히어로·조건 요약 줄·카드 3열 구조에서 표시가 시각적으로 뒤로 밀리기 쉽다 → DOM 순서 테스트 + 재배치 클래스 금지 검사 + 폭별 스크린샷(완료 기준 5).
- **성능**: 사진 도입으로 시작 화면 LCP가 나빠질 수 있다(M2 기록 100). 정적 내보내기라 자동 최적화가 없다 → 사람이 미리 크기별 WebP를 만든다. 결과는 T-053에서 측정.
- **사진 위 글자 대비**: 테스트로 계산할 수 없다 → 덮개 토큰 + 사람 확인.
- **라임 남용**: 강조 의미가 흐려지고 대비 문제가 생긴다 → 3.7 규칙과 소스 검사.
- **결과 데스크톱 3열과 D-028**: 모바일의 "1순위 강조" 원칙을 데스크톱에서 같은 크기 카드로 바꾸는 것은 시안 채택에 따른 해석이다. 1순위는 배지·테두리·순서로만 강조된다. 사용자가 데스크톱에서도 1순위를 크게 원하면 T-046 범위가 바뀐다.
- **저장 기능의 개인정보 해석**: 기기 안 저장이라도 안내가 필요한지 법적 판단은 하지 않았다(전문가 확인 필요, M3 T-030과 연결).
- **공통 헤더와 정적 HTML**: `/browse`가 빌드 HTML에 목록이 없는 문제(m2.md 10장 C)는 그대로다. 헤더만 미리 그려진다.
- **기존 테스트 대량 수정**: 화면 문구·구조가 바뀌어 화면 테스트가 많이 깨질 수 있다. 카드마다 "동작 무변경" 테스트는 고치지 않고 통과시키는 것을 원칙으로 한다.

### 미확인
- 시안 색 값(라임 `#c5f23a`, 히어로 `#0f2a36` 등)은 그림에서 눈으로 읽은 **시안에서 추정** 값이다. 원본 디자인 파일 값은 받지 못했다.
- 스톡 사진 라이선스 조건(구입 전이라 없음), 사진 파일 크기·LCP 영향.
- 특성 데이터의 공개 출처 존재 여부와 이용 조건(T-052, **fury 조사 필요**).
- 로컬 저장에 대한 개인정보 안내 의무(전문가 확인 필요).
- "PaddleFit" 영문 상표 사용 가능 여부(상표 검색 안 함).
- 시안의 데스크톱 화면 폭(그림 기준 1536px 근처로 보임, 시안에서 추정) — 설계는 1440px까지 확인.
- 웹 글꼴은 계속 보류(m2-review 8장). 시안의 굵은 제목 글꼴 느낌은 시스템 글꼴 700으로는 다르게 보일 수 있다.

### 되돌릴 수 있는지
- 토큰 추가·화면 스타일은 카드 단위 브랜치라 되돌리기 쉽다. 저장 기능은 키 버전(`v1`)이 있어 형식 변경 시 이전 데이터를 버리는 방식으로 정리할 수 있다. 데이터 스키마·엔진은 이번에 바꾸지 않는다.

## 10. 외부 검토 반영 (GPT, 2026-11-17)
- 사용자가 GPT에 브리프(docs/design/gpt-brief.md)와 소스 ZIP을 주고 받은 검토 3건을 메인 세션이 대조했다
  1. 결과 데스크톱 4:8 배치에서 카드가 좁아짐 → 계산 확인(1024px 약 195px, 1152px 이상 약 223px). **사용자 결정 D-037: 상단 가로 조건 요약 + 카드 3열 전체 폭**으로 변경(약 304~347px)
  2. 저장 결과에 적합도 라벨을 다시 보이지 않는 대신 안내 필요 → T-050 수용 기준에 안내 문구 추가
  3. 실기기에서 구매 버튼·비교 표 조작 확인 → T-053에 사용자 실기기 확인 목록 추가
- GPT가 제안한 "결과 화면 시안 2개 비교"는 숫자 차이가 분명해 생략하고, 구현 후 1024·1440px 화면으로 확인한다
