# T-022 가격 재확인과 제품 구성 보강

## 목표
가격 확인일 만료(2026-12-15쯤 `check:release` 실패) 전에 20개 가격을 다시 확인하고, 30일마다 반복할 절차를 문서로 남긴다. 질문 조합별로 맞는 제품이 몇 개인지 보이게 하고, 비어 있는 표준형을 채운다. 2단계 기획안 4장 M1 "데이터 보강", 9장, D-028.

## 진행 순서
1. **조합별 제품 수 보고** (코드): `npm run data:check -- --coverage`가 형태 4 × 예산 답 4 × 대회 여부 2 = 32개 조합마다 하드 필터를 통과하는 제품 수를 표로 출력한다. 엔진의 필터(`src/lib/recommend/filter.ts`)와 답변 변환(`src/lib/quiz/answers.ts`)을 그대로 써서 실제 화면 결과와 같은 기준으로 센다. 2개 미만 조합을 따로 표시한다. 경고·실패가 아니라 정보 출력이다(배포를 막지 않는다).
2. **가격 재확인 절차 문서** (`docs/data/price-check.md`): 주기(30일), 확인할 곳(출처의 판매처 상품 페이지), 기록할 것(가격, 확인일, 판매 중 여부, 옵션 차이), 품절·단종 처리, 가격이 크게 바뀌었을 때 순위 비교.
3. **1차 가격 재확인**: 20개 판매처 페이지를 앱 내 브라우저로 직접 열어 판매가·판매 상태를 확인한다. 바뀐 값은 **확인표로 먼저 보여 주고 승인 후** `price_krw`·`price_checked_at`을 고친다. 품절·판매 중지는 따로 보고한다.
4. **표준형 보강**: 표준형(제조사 표기 또는 D-018 치수 규칙) 후보를 국내 판매처·제조사에서 조사해 2개 이상 고른다. 입문 가격대와 대회 승인 제품을 우선한다. 지금까지처럼 초안(`data/staging`) → 확인표 → 승인 → 승격.
5. 1의 보고를 다시 돌려 보강 전후를 비교하고, 남은 빈 조합을 기록한다.

## 건드리지 말 것
- 추천 엔진의 점수·필터 로직(`src/lib/recommend`)은 읽기만 한다. 예외: 데이터 점검 CLI(Node 직접 실행)가 불러올 수 있게 `filter.ts`·`profile.ts`·`answers.ts`·`questions.ts`의 값 import 6곳에 `.ts` 확장자만 붙인다(동작 변화 없음, `data/check.ts`와 같은 방식)
- 화면 코드(`src/components`, `src/app`)
- 사용자 개인 폴더(바탕화면 `03_개인` 등)의 수집 자료는 읽지 않는다. 판매처·제조사 사이트에서 직접 확인한다

## 확인하지 못한 것
- 판매처가 가격을 옵션별로 다르게 받는 경우 어느 값을 기준으로 할지는 제품마다 확인표에서 정한다
- 표준형 + 저가 + 대회 승인 조합을 채울 제품이 시장에 있는지는 조사 전이라 모른다
