## 진행 순서
1. **후보 찾기**: 국내 판매처(피앤피노 등, 지금 구매 링크와 같은 곳)에서 부족한 형태·가격대 제품을 찾는다. 앱 안 브라우저로 판매처 목록·상품 페이지를 직접 읽는다(자동 수집 아님, staging README의 조사 방법)
   - 후보마다: 판매가(할인가), 형태 근거(제조사 표기 또는 길이·폭), 코어 두께·무게 공개 여부, USA Pickleball 승인 목록 등재 여부
   - **후보표를 먼저 보여 드리고**, 초안을 만들 제품을 고르시게 한다(1차 확인)
2. **초안**(`data/staging/<id>.draft.json`): 제조사 공식 페이지 → 없으면 판매처 표기(D-025). 값마다 원문·URL·읽은 날(`evidence`, `source_meta`). 모르는 값은 `null`, 추정하지 않는다. 형태는 D-018(제조사 표기 우선, 없으면 치수 규칙)
3. **확인표**: 제품마다 값·출처·사람이 볼 것(경계 치수, 판매처 표기, 승인 대조)을 정리해 **승인을 받는다**(2차 확인)
4. **승격**: 승인된 제품만 `data/paddles.json`에. 구매 링크(`purchase`, 출처와 같은 판매처 주소)·가격 확인일 포함
5. **전후 비교**: 조합 보고 전후, 추천 순위 변화(T-022처럼 전체 답변 조합에서 몇 개가 바뀌었는지, 새 제품이 1위가 되는 조합), 남은 빈 조합과 사유

- **사용자 개인 폴더의 수집 자료**(바탕화면 `03_개인` 등)는 읽지 않는다. 판매처·제조사 사이트에서 직접 확인한다

## 에이전트 사용
- 외부 조사 에이전트(fury)는 이 세션에서 부를 수 없고, 웹 읽기 에이전트는 제조사 사이트에서 막혀 검색 요약 값을 보고한 적이 있다(staging README). 그래서 **메인 세션이 앱 안 브라우저로 직접 읽는다**

## 확인하지 못한 것
- 표준형 10~30만 원대, 길쭉한 형·넓은 형 10만 원 이하 승인 제품이 국내 판매처에 있는지(조사 전)
- 입문 가격대 제품은 코어 두께를 공개하지 않는 경우가 많다(후보 목록 v0.2). 코어를 모르면 넣지 않는다
