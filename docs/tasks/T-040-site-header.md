# T-040 공통 헤더

## 목표
질문 화면을 뺀 모든 화면 맨 위에 같은 헤더(로고·메뉴·검색)를 둔다. 화면마다 달랐던 위쪽 길("질문 없이 둘러보기", "← 처음으로")을 헤더로 합친다. 기획: docs/plan/m2.5-redesign.md 2장 헤더 행·3.6·4.4, 7장 T-040 행, U3·U6(D-038).

## 헤더 구성
- 순서: 로고("패들핏", 앱 아이콘 그림 + 한글, `/`로 이동) → 메뉴 "내 패들 찾기"(`/quiz`) · "패들 둘러보기"(`/browse`) → 검색 아이콘(`/browse#search`)
- "내 패들 찾기"는 시작 버튼과 같이 이 탭의 이전 답을 지우고 질문 화면으로 간다(`clearAnswers`)
- 360px처럼 좁은 화면에서는 메뉴 글자를 "패들 찾기"·"둘러보기"로 줄인다. 햄버거 메뉴는 쓰지 않는다
- `aria-current="page"`: 시작 화면에서는 로고, 둘러보기에서는 "패들 둘러보기"
- 넣지 않는 것
  - 저장 아이콘: T-050에서 `/saved`와 함께 넣는다
  - "추천 가이드" 메뉴(U3), 계정 아이콘(로그인 없음), 영문 "PaddleFit"(U6)
- 폭: 바깥 최대 72rem(`max-w-6xl`), 좌우 20px(1024px 이상 32px)
  - 본문은 아직 최대 36rem이라, 데스크톱에서는 헤더가 본문보다 넓다
  - 본문 폭은 이후 화면 카드(T-043·T-045·T-048)에서 넓힌다
- 배치: 각 `page.tsx`에서 `<main>` 앞에 둔다. 헤더가 `banner` 영역이 되고, 본문 맨 앞의 대가 표시는 헤더 다음·`h1` 앞이 된다(기획 3.6). 라우트 그룹은 쓰지 않는다(4.4 권고)
- 검색 아이콘을 눌러 온 뒤 검색칸에 포커스를 주는 동작은 T-048에서 만든다. 이 카드에서는 링크만 둔다

## 수용 기준
- [ ] 시작·둘러보기·결과·공유받은 화면·404의 5개 화면에 헤더가 1개씩 있다. 질문 화면에는 없다
- [ ] 현재 화면 링크에 `aria-current="page"`가 있다(시작 화면은 로고, 둘러보기는 메뉴)
- [ ] 헤더의 링크가 모두 키보드(Tab)로 이동되고, 포커스 링이 보인다
- [ ] 아이콘만 있는 링크(검색)에 접근 가능한 이름이 있다
- [ ] 대가 표시가 있는 화면(결과·둘러보기·공유받은 화면)에서 DOM 순서가 헤더 → 대가 표시 → `h1`이다(테스트)
- [ ] 시작 화면의 위쪽 바(로고·"질문 없이 둘러보기")와 둘러보기·공유받은 화면의 "← 처음으로"를 헤더로 대신한다. 결과 화면의 "전체 둘러보기"와 하단 고정 시작 버튼은 그대로 둔다
- [ ] 360px에서 헤더가 한 줄에 들어가고 가로 스크롤이 없다(브라우저 확인)
- [ ] 로고 바탕은 계속 상표 색(`--brand`)이다(tokens.test의 로고 검사 대상을 헤더 파일로 옮김)
- [ ] `npm run check` 통과, 빌드 통과
