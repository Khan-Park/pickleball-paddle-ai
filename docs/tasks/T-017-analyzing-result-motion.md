# T-017 분석 중 화면과 결과 등장 연출

## 목표
마지막 질문과 결과 사이에 "분석 중" 화면을 넣고(D-028), 결과 화면이 나타날 때 순서 있는 연출과 읽는 동안의 자리 표시를 준다. 기획: docs/plan/phase2.md 5.3, 6.2·6.3·6.4.

## 할 일
1. **분석 중 화면** (5.3, 6.3)
   - 결과 화면(`/result`)의 첫 상태로 만든다(별도 주소 없음, 6.4)
   - 구성: 패들이 공을 치는 단순한 선 그림 애니메이션(직접 그린 SVG) + 단계 문구 3개가 차례로 체크 + "건너뛰기" 버튼
     - 문구: "조건 확인" → "{실제 제품 수}개 패들 스펙 비교" → "추천 정리". 제품 수는 데이터 개수로 채운다(꾸민 숫자 금지)
   - 시간: 단계당 약 350ms, 전체 약 1.05초. 화면 아무 곳이나 누르거나 "건너뛰기"를 누르면 바로 결과
   - 언제 보여 주나: 질문 화면에서 막 제출했을 때만. 질문 화면이 제출 직전에 탭 저장소에 표시를 남기고, 결과 화면이 그 표시를 보고 한 번 보여 준 뒤 지운다
     - 새로고침이나 결과 주소로 바로 들어오면 보여 주지 않는다
     - "답변 고치기"로 돌아가 다시 제출하면 짧게(약 0.5초) 보여 준다(반복 대기 방지)
     - 동작 줄이기 설정이면 보여 주지 않는다
   - 화면 낭독기: 단계 문구를 `role="status"`로 알리고, 그림은 숨긴다
2. **결과 등장 연출** (6.2)
   - 결과 카드가 1→2→3순위 순서로 아래에서 떠오르며 등장(카드당 280ms, 80ms 간격)
   - 저장된 답변을 읽기 전 잠깐 보이는 "답변을 확인하고 있습니다" 문구를 T-015 카드 스켈레톤으로 바꾼다(문구는 화면 낭독기용으로 유지)
   - 적합도 막대는 결과 카드 재설계(T-018)에서 만든다. 이 카드에서는 다루지 않는다
3. **테스트**: 분석 중 표시 규칙(제출 직후만, 한 번만, 다시 제출 시 짧게, 건너뛰기, 동작 줄이기면 생략), 제품 수 문구, 스켈레톤

## 수용 기준
- [x] 질문을 끝내면 분석 중 화면이 약 1초 보인 뒤 결과가 나오고, 누르면 바로 넘어간다
- [x] 새로고침·직접 접속에서는 분석 중 화면이 나오지 않는다
- [x] 다시 제출하면 짧게 나온다. 동작 줄이기면 나오지 않는다
- [x] 단계 문구의 제품 수가 실제 데이터 개수와 같다
- [x] 결과 카드가 순서대로 등장한다. 읽는 동안 스켈레톤이 보인다
- [x] 결과 화면의 기존 동작(대가 표시, 조건 완화, 답변 고치기)과 테스트가 그대로 통과한다
- [x] 375px 브라우저 확인, `npm run check`·`npm run build` 통과

- 브라우저(정적 빌드, 375px): 마지막 답을 고르면 분석 중 화면이 나오고 단계가 약 350ms마다 체크되며 "22개 패들 스펙 비교"(실제 데이터 수)가 보인다. 답을 고른 뒤 약 1.5초에 결과 카드 3개(선택 표시 150ms 포함). 결과 주소로 다시 들어가면 나오지 않는다. 콘솔 오류 없음
- 표시 방식: 질문 화면이 제출 직전 탭 저장소에 "full" 또는 "short"를 남기고, 결과 화면이 읽은 뒤 지운다. React 개발 모드에서 초기화 함수가 두 번 불려도 값이 남도록 읽기와 지우기를 나눴다
- 동작 줄이기에서 생략되는지는 테스트로만 확인했다
