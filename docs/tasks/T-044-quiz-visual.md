# T-044 질문 화면 시각 개편

## 목표
질문 화면의 진행 표시와 선택 카드를 리디자인 방향(시안 모바일 02)에 맞게 다듬는다. 질문 내용·순서·자동 진행(150ms)·답 저장 방식은 그대로 둔다. 기획: docs/plan/m2.5-redesign.md 2장 설문 행·3.7, 7장 T-044 행, U5(질문 선택지에 사진 없음).

## 지금 상태
이미 갖춰진 것이 많다. 선택 표시는 색과 체크 아이콘을 함께 쓰고, 진행 막대는 틸이며 scaleX로 늘어난다. 선택 카드 높이는 64px 이상이고, 형태 질문에는 T-041 패들 그림이 나온다. 그래서 이 카드는 **생김새 다듬기**가 중심이다.

## 바꿀 것
1. **진행 표시**
   - 막대를 조금 두껍게 한다(8px → 10px). 채움은 틸 그대로다
   - 채움 끝에 공 그림(T-041 `BallIcon` 작은 크기)을 붙여 함께 움직인다
     - 라임은 꾸밈에만 쓴다는 규칙(3.7)에 맞는다. 장식이라 화면 낭독기에서 숨긴다
     - 움직임은 transform만 쓴다. 공을 감싼 칸을 막대 폭만큼 두고 translateX로 민다(left·width를 바꾸지 않는다)
     - 동작 줄이기를 켜면 전역 규칙으로 움직임 없이 바로 그 자리에 놓인다
   - "3 / 7"은 지금처럼 글자로 둔다
2. **질문 머리**: 제목 위에 작은 줄을 둔다. 예: "질문 3"(틸 글자). 제목 크기는 데스크톱에서 한 단계 키운다
3. **선택 카드**
   - 고르지 않은 카드: 옅은 그림자(`shadow-card`)를 넣는다
   - 고른 카드: 테두리를 2px 틸로 하고, 바탕은 `accent-soft`, 체크 원은 지금처럼 둔다
   - 테두리가 두꺼워져도 글자가 밀리지 않게, 고르지 않은 카드는 같은 두께의 투명한 테두리를 쓴다
   - 형태 질문의 패들 그림은 고르면 틸색이 된다(지금은 늘 남색)
4. **데스크톱**: 질문 칸의 최대 폭(36rem)은 그대로 두고, 위아래 여백만 넓힌다. 질문 화면에는 공통 헤더를 넣지 않는다(T-040)

## 수용 기준

- [x] 선택 표시는 색 + 체크 아이콘 + `aria-pressed`이다(테스트)
- [x] 진행 막대 채움은 틸(`bg-accent`)이고, 라임은 공 그림에만 있다(테스트: 라임 클래스가 진행 영역의 공 그림 밖에 없음)
- [x] 공 그림 칸이 transform(translateX)으로 진행률만큼 움직이고, 화면 낭독기에서 숨겨진다(테스트)
- [x] 360px에서 선택 카드 높이가 64px 이상이고, 가로 스크롤이 없다(브라우저 측정)
- [ ] 밝은·어두운 화면에서 고른 카드와 고르지 않은 카드가 구분된다(스크린샷 또는 사람 확인 — 스크린샷 실패, 사용자 확인 대기)

## 결과 (2026-11-17)
- 진행 막대: 두께 10px, 채움 틸 그대로. 채움 끝을 따라가는 공 그림(라임)을 막대 폭만 한 칸에 두고 translateX로 민다
- 질문 머리: "질문 N"(틸, 화면 낭독기에는 숨김) + 제목(데스크톱에서 한 단계 큼)
- 선택 카드: 테두리는 늘 2px. 고르지 않은 카드는 투명 테두리 + 1px 바깥 선 + 그림자, 고른 카드는 틸 테두리 + `accent-soft`. 형태 그림은 고르면 틸색
- 데스크톱 위아래 여백 확대
- 테스트 3개 추가, 기존 질문 화면 테스트 24개는 고치지 않고 통과. 전체 524개 통과, 빌드 통과
- 브라우저 측정(360px, 로컬 빌드): 선택 카드 높이 64px(3개 모두), 가로 스크롤 없음, 공 그림 중심(123px)이 채움 끝(123px)과 일치
- 스크린샷: 브라우저 창이 가려져 시간 초과로 실패했다. 고른 카드와 고르지 않은 카드의 구분은 사용자가 확인해야 한다
