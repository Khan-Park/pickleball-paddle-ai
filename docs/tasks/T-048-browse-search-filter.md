# T-048 둘러보기 검색·브랜드·무게 필터·데스크톱 격자

## 목표
둘러보기에 검색칸, 브랜드 필터, 무게 필터를 더한다. 1024px 이상에서는 왼쪽 열에 필터를 펼치고, 오른쪽에 목록을 2열 격자로 보여 준다. 헤더의 검색 아이콘(`/browse#search`)으로 오면 검색칸에 바로 포커스가 가게 한다. 기획: docs/plan/m2.5-redesign.md 5.2·4.4, 7장 T-048 행, D-030.

## 설계
- **검색**
  - 브랜드와 모델 이름을 붙인 글자에서 부분 일치로 찾는다. 대소문자와 공백은 무시한다. 예: "joola per", "JOOLAPerseus"
  - 화면 안 상태로만 둔다. 주소(쿼리)나 저장소에 남기지 않는다(지금 필터 원칙)
  - 한글 브랜드 이름("줄라")은 데이터에 없어서 찾지 못한다. 0건일 때 안내에 "영문 브랜드·모델 이름으로 찾아 주세요"를 적는다
- **브랜드**: 데이터에 있는 브랜드로 칩 목록을 만든다(지금 13개, 이름 순). 여러 개를 고를 수 있다
- **무게**: 3구간 칩. 가벼움(7.3oz 미만) · 중간(7.3~8.4oz) · 묵직함(8.4oz 초과)
  - 판정은 엔진의 `weightBand`를 그대로 불러 쓴다. 그래서 경계값(7.3·8.4는 중간)이 퀴즈·추천과 같다
  - 새 수치는 만들지 않는다
- **필터 순서**: 검색 → 형태 → 브랜드 → 무게 → 가격 → 대회 승인
  - 모든 조건은 함께(그리고) 적용한다
  - 정렬은 가격 낮은 순 그대로(D-030)
  - "필터 지우기"는 검색어까지 지운다
  - 고른 조건 요약 줄에 검색어·브랜드·무게도 넣는다
- **`filterAndSort` 원칙 유지**: 스펙 필드와 이름만 받는다. 구매 링크·제휴·가격 비교 검색어는 읽지 않는다(기존 소스 검사)
- **헤더 검색 아이콘**
  - 둘러보기에 들어올 때 주소 해시가 `#search`면 검색칸에 포커스한다
  - 이미 둘러보기 화면에 있을 때 아이콘을 눌러도(해시 변경) 포커스한다
  - 모바일에서는 접힌 필터를 열지 않아도 검색칸이 보이게, 검색칸을 필터 묶음 밖(목록 위)에 둔다
- **데스크톱 배치**(1024px 이상, T-046의 `useMediaQuery`)
  - 왼쪽 3칸: 필터를 늘 펼친다. 접기 버튼은 없다
  - 오른쪽 9칸: 검색칸 + 개수 + 목록 2열 격자
  - 모바일은 지금 구조(필터 접힘, 한 열)

## 수용 기준
- [ ] 검색 단위 테스트
  - [ ] 대소문자·공백을 무시하고 브랜드+모델에서 부분 일치한다
  - [ ] 빈 검색어면 거르지 않는다
- [ ] 무게 구간이 엔진 `weightBand`와 같다(경계 7.3·8.4oz와 그 바로 옆 값 테스트)
- [ ] 브랜드 목록이 데이터에서 만들어지고, 중복 없이 이름 순이다(테스트)
- [ ] 조건 조합(검색 + 브랜드 + 무게 + 기존 필터), "필터 지우기", 0건 화면 테스트
- [ ] 필터·검색이 주소·`sessionStorage`·`localStorage`에 남지 않는다(테스트)
- [ ] `#search`로 들어오면 검색칸에 포커스가 간다. 해시가 바뀔 때도 간다(테스트)
- [ ] `browse.ts`가 구매 필드를 읽지 않는다(기존 소스 검사 통과)
- [ ] 데스크톱(폭 조건 흉내): 필터가 펼쳐져 있고 접기 버튼이 없으며, 목록이 격자다(테스트)
- [ ] 1024px·375px에서 가로 스크롤이 없다(브라우저 측정)
- [ ] `npm run check` 통과, 빌드 통과
