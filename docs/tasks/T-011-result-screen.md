# T-011 결과 화면

## 목표
`/result`에서 답변으로 추천을 계산해 카드 3개와 안내 문구를 보여 준다. 후보가 없으면 조건 완화를 제안한다. 설계: docs/design/ui-flow.md 3~4장.

## 수용 기준
- [x] 답변이 없거나 깨졌으면 `/quiz`로 보낸다
- [x] 추천 카드: 순위, 적합도 라벨(점수 숫자는 보여 주지 않음), 추천 이유, 주의 문구, 스펙, 가격과 확인일, 대회 승인 표시
- [x] 대회 승인 미확인 제품은 숨기지 않고 "대회 승인 여부 미확인"으로 적는다
- [x] 구매 버튼은 링크가 있을 때만 그리고, 제휴 링크면 버튼 바로 아래에 대가 표시를 함께 그린다(CLAUDE.md 규칙 3). 링크 유무는 순위에 영향이 없다
- [x] 엔진에는 `purchase`를 뺀 스펙만 넘긴다(규칙 1)
- [x] 후보 0개: 조건 완화 버튼(예산 올리기, 승인 조건 빼기, 둘 다). 누르면 다시 추천하고 저장된 답변은 바꾸지 않는다
- [x] 안내: 스펙 기준 추천, 수수료와 순위 무관, 가격 안내, 팔 불편을 고른 경우의 안내(의학적 효과를 단정하지 않음), 그립 고르는 법
- [x] 가격 확인일이 30일을 넘으면 "가격 변동 가능"
- [x] 화면 테스트(jsdom) 11개, `npm run check`·`npm run build` 통과, 브라우저(폭 375px)에서 실제 데이터로 확인

## 알려 둘 점
- Next.js 16은 미리 그리는 화면에서 `new Date()`를 읽으면 빌드가 실패한다. 오늘 날짜와 저장된 답변은 `useSyncExternalStore`로 브라우저에서만 읽는다.
- 제품 데이터는 `/result` 페이지에서 빌드할 때 스키마로 검증한다. 형식이 틀리면 빌드가 실패한다.
- 제품 전체 정보(구매 링크 포함)는 화면 표시용으로 브라우저에 전달된다. 엔진 호출 직전에 `purchase`를 뗀다.
- 지금은 모든 제품의 구매 링크가 비어 있어 버튼이 나오지 않는다.
- 선호 모양 선 그림, 대가 표시 문구의 법적 검토는 T-012에서 다룬다.
