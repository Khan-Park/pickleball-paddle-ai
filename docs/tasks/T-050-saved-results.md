# T-050 로컬 결과 저장(`/saved`)

## 목표
로그인 없이 추천 결과를 이 기기 브라우저에 저장하고, `/saved` 화면에서 다시 보거나 지울 수 있게 한다. 결과 화면에 "결과 저장" 버튼을 두고, 헤더에 저장 아이콘(→ `/saved`)을 단다. 기획: docs/plan/m2.5-redesign.md 5.1, 7장 T-050 행, U2(180일 자동 삭제, D-038).

## 설계
- **보관**(새 `src/lib/shared/saved.ts`, 순수 함수 + 얇은 저장소 함수)
  - `localStorage` 키 `pb.saved.v1` 하나만 쓴다. 서버·주소로 보내지 않는다
  - 한 건의 키는 정확히 6개다: `id`, `saved_at`, `paddle_ids`, `conditions`, `relaxed`, `scoring_version`
    - `id`: 무작위 문자열(`crypto.randomUUID`, 없으면 대체)
    - `saved_at`: 이 기기 날짜 `YYYY-MM-DD`(`todayLocal`)
    - `paddle_ids`: 화면에 보인 추천 순서대로, 최대 3개
    - `conditions`: 지금 결과 화면 조건 칩과 같은 문구(`conditionChips`를 그대로 불러 쓴다. 팔 불편은 원래 빠져 있다)
    - `relaxed`: 조건을 바꿔서 다시 찾은 결과인지
    - `scoring_version`: 저장할 때의 엔진 판 번호
  - 저장하지 않는 것: 팔 불편 답, 질문 답 원문, 점수·적합도 라벨·이유 문장, 구매 링크·가격
  - **최대 10건**: 새로 저장해 11건이 되면 가장 오래된 것부터 지운다. 지웠으면 결과로 알려 화면이 안내한다
  - **같은 결과**: `paddle_ids`와 `conditions`가 같으면 새로 만들지 않고 날짜만 오늘로 바꿔 맨 앞으로 올린다
  - **180일(U2)**: 읽을 때 오늘과 `saved_at`이 180일 넘게 차이 나면 버린다. 버린 게 있으면 저장소도 다시 쓴다. 오늘 날짜는 인자로 받는다(테스트에서 주입)
  - **읽기 검사**: 값이 깨졌거나 형식이 다른 건은 버린다(zod). 키가 6개를 넘는 건도 버린다
  - **저장소를 못 쓸 때**(사생활 모드 등): 쓰기 실패를 `"unavailable"`로 돌려준다. 화면은 계속 동작한다
  - 순서는 최근 저장이 앞이다
- **결과 화면**(`Result.tsx`)
  - 아래 행동 줄에 "결과 저장" 버튼을 둔다. 추천이 1개 이상일 때만 보인다
  - 저장하면 토스트 "결과를 저장했습니다"를 띄우고, 버튼 옆에 "저장한 결과 보기"(→ `/saved`) 링크를 보인다
  - 10건이 넘어 지웠으면 "가장 오래된 저장 1건을 지웠습니다"를 덧붙인다
  - 실패하면 버튼 옆에 "이 브라우저에서는 저장할 수 없습니다"를 보인다
  - 위 안내는 화면 낭독기용 상태 영역으로도 알린다
- **`/saved` 화면**(새 `src/app/saved/page.tsx`, `src/components/saved/Saved.tsx`)
  - 순서: 헤더 → (제휴 링크가 있으면) 대가 표시 → `h1` "저장한 추천" → 안내 → 목록
  - 안내 두 줄
    - "저장 당시 추천된 제품입니다. 가격·승인은 지금 기준입니다."
    - "이 기기 브라우저에만 저장되며, 브라우저 데이터를 지우면 사라집니다. 저장 후 180일이 지나면 자동으로 지워집니다."
  - 한 건 카드
    - 저장 날짜, 조건 칩(누를 수 없는 글자), 조건을 바꿔 찾은 결과면 그 표시
    - 제품은 공유받은 화면과 같은 `ProductRow`(순위 번호 포함)로 지금 데이터 기준으로 보인다. 누르면 "자세히" 시트
    - 지금 데이터에 없는 제품은 "지금은 목록에 없는 제품 N개"로 적는다
    - "지우기" 버튼(접근 가능한 이름에 날짜를 넣는다)
  - 적합도 라벨·점수·이유 문장은 보이지 않는다
  - 아래에 "지금 조건으로 다시 받기"(질문 시작 버튼)와 "모두 지우기"
    - "모두 지우기"는 한 번 더 확인한다(같은 자리에 "정말 모두 지울까요?" + "모두 지우기"·"취소"). 브라우저 확인 창(confirm)은 쓰지 않는다
  - 저장한 것이 없으면 빈 화면 안내와 질문 시작 버튼
  - 메타: `robots` noindex. sitemap에 넣지 않는다(`SITEMAP_PATHS` 그대로)
- **헤더**(`SiteHeader.tsx`)
  - 검색 아이콘 옆에 책갈피 아이콘 링크 `/saved`, 이름 "저장한 추천"
  - 저장 화면에서는 `aria-current="page"`(`current="saved"` 추가)

## 수용 기준
- [ ] `saved.ts` 단위 테스트
  - [ ] 저장 JSON 한 건의 키 목록이 정확히 6개 목록과 같다. 팔 불편·답 원문·점수·라벨·구매 필드가 없다
  - [ ] 11번째 저장에서 가장 오래된 1건이 지워지고, 지웠다는 결과가 나온다
  - [ ] 같은 `paddle_ids`·`conditions`면 건수가 늘지 않고 날짜만 바뀌며 맨 앞으로 온다
  - [ ] 180일은 남고 181일은 읽을 때 지워진다(날짜 주입). 지운 뒤 저장소 값도 바뀐다
  - [ ] 깨진 값·형식이 다른 건·키가 더 있는 건은 버린다
  - [ ] 저장소 쓰기가 실패하면 `"unavailable"`이다
- [ ] `saved.ts`가 구매·제휴 필드를 읽지 않는다(소스 검사)
- [ ] 결과 화면 테스트
  - [ ] "결과 저장"을 누르면 저장소에 1건이 생기고 "저장한 결과 보기" 링크가 나온다
  - [ ] 팔 불편을 고른 답으로 저장해도 저장 값에 팔 불편 흔적이 없다
  - [ ] 저장소가 막히면 "이 브라우저에서는 저장할 수 없습니다"가 나오고 화면은 그대로다
- [ ] `/saved` 화면 테스트
  - [ ] 저장 2건이 최근 순으로 보이고, 날짜·조건 칩·제품 이름이 나온다
  - [ ] 두 안내 문구와 "지금 조건으로 다시 받기"가 있고, 적합도 라벨이 없다
  - [ ] 없어진 제품은 "지금은 목록에 없는 제품" 안내로 나온다
  - [ ] "지우기"는 그 건만, "모두 지우기"는 확인 뒤 전부 지운다(저장소 키 삭제). "취소"는 아무것도 지우지 않는다
  - [ ] 빈 상태 화면
  - [ ] 제휴 링크가 있으면 대가 표시가 `h1`보다 DOM 앞이고 접힌 영역 밖이다
- [ ] 헤더 테스트: 저장 아이콘 링크가 `/saved`이고, 저장 화면에서 `aria-current="page"`
- [ ] `/saved`에 noindex 메타가 있고 sitemap에 없다(테스트)
- [ ] 화면 소스 검사(copy.test.ts) 통과: "AI" 없음 등
- [ ] 375px·1024px에서 `/saved` 가로 스크롤이 없다(브라우저 측정)
- [ ] `npm run check` 통과, 빌드 통과
