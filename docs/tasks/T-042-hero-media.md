# T-042 히어로 미디어 부품 + 사진 후보

## 목표
홈·결과 화면의 짙은 히어로 띠에 쓸 부품(`HeroMedia`)을 만든다. 사진이 없으면 직접 그린 대체 배경으로 그려지게 해서, 사진이 정해지기 전에도 배포할 수 있게 한다. 사진 출처·라이선스 기록 양식도 만든다. 함께 스톡 사진 후보를 찾아 제시한다(U7). 기획: docs/plan/m2.5-redesign.md 3.3·3.7·4.1, 7장 T-042 행, D-035 (1), D-038 U7.

## 부품 설계
- `HeroMedia({ slot, className, children })`
  - `slot`: `"home-wide" | "home-tall" | "result"` 중 하나. 사진 자리 이름이다
  - 바탕은 `--hero`이고, 그 위에 `children`(제목·버튼)을 올린다
  - 글자색은 `--on-hero`, 포커스 링은 `--focus-on-hero`로 정해 둔다
- **사진 목록**: 새 `src/lib/shared/hero-photos.ts`에 자리별 사진 정보를 둔다
  - 정보: 파일 경로, 폭·높이, 출처 기록 id
  - 지금은 세 자리 모두 비어 있다(`null`). 사진이 정해지면 이 파일과 `public/`만 바꾼다
- **사진이 없을 때(대체 배경)**: 아래를 SVG로 그린다. 모두 토큰 색이고 장식이다(`aria-hidden`)
  - 짙은 히어로 색에서 틸 쪽으로 옅어지는 그라데이션
  - 코트 선 무늬(가는 선, 낮은 불투명도)
  - 패들 그림과 공 그림(T-041)
- **사진이 있을 때**
  - `<img>`에 `width`·`height`를 적어 화면이 밀리지 않게 한다(CLS)
  - 장식이라 `alt=""`로 둔다
  - 위에 덮개(`--hero-scrim`, 75%)를 깔아 글자 대비를 지킨다
  - 첫 화면에 보이는 그림이라 지연 로딩하지 않는다: `loading="eager"`, `fetchPriority="high"`, `decoding="async"`
  - 정적 내보내기라 `next/image` 최적화를 쓰지 않는다. 사진은 크기별 WebP로 미리 만들어 `public/hero/`에 둔다
- **라이선스 기록**: 새 `docs/design/assets.md`
  - 양식: 파일 / 자리 / 출처 페이지 / 작가 / 라이선스와 원문 주소 / 받은 날 / 허용 범위(웹·상업·수정) / 확인한 사람
  - 테스트: 사진 목록에 있는 파일은 모두 이 문서에 기록이 있어야 한다. 기록 없는 사진은 넣을 수 없다
- **이 카드에서 하지 않는 것**: 화면에 넣기. 홈은 T-043, 결과는 T-045에서 쓴다. 그래서 화면은 바뀌지 않는다

## 사진 후보 찾기 (U7)
1. **fury(외부 조사)**: 상업 이용이 무료인 라이선스(Unsplash·Pexels 등) 사진에서 자리별 후보를 2~3장씩 찾는다
   - 기준: 웹·상업 이용 허용, 브랜드 로고·제품명이 안 보임, 알아볼 수 있는 얼굴 없음, 피클볼 코트·패들·공 분위기
   - 자리: 홈 가로형(데스크톱), 홈 세로형(모바일), 결과 히어로(가로 띠)
   - 결과물: `docs/design/photo-candidates.md`. 사진 페이지 주소, 작가, 라이선스 원문 주소와 짧은 인용, 확인일
   - 내려받지 않는다
2. **메인 세션**: 후보 페이지를 브라우저로 열어 로고·얼굴이 보이는지 눈으로 확인하고, 탈락한 것은 표시한다
3. **사용자**: 후보를 고르고 라이선스 원문을 확인한다
4. 승인을 받은 뒤 파일을 내려받는다. WebP 변환, `public/hero/`, 사진 목록, `assets.md` 기록은 별도 커밋으로 한다. 이 카드의 수용 기준에는 넣지 않는다
- hawkeye는 부르지 않는다. 라이선스 원문은 사용자가 직접 확인하고(기획 3.3), 사진 내용은 메인이 눈으로 확인하기 때문이다

## 수용 기준
- [x] 사진 목록이 비어 있어도 세 자리 모두 대체 배경으로 그려지고, `<img>`는 없다(테스트)
- [x] 사진을 지정하면 `<img>`에 `width`·`height`·`alt=""`·`loading="eager"`가 붙고, 덮개가 사진 위·글자 아래에 있다(가짜 사진 정보로 테스트)
- [x] 장식 요소(SVG·사진·덮개)는 모두 화면 낭독기에서 숨겨지고, `children`은 읽힌다
- [x] 대체 배경 그림에 고정 색 값이 없다(`currentColor`·`var(--토큰)`만)
- [x] 사진 목록의 파일마다 `docs/design/assets.md`에 기록이 있다(테스트. 지금은 0건이라 통과)
- [x] 덮개 위 글자 대비는 T-039 테스트(덮개 합성색 4.5:1)가 지킨다. 실제 사진 위 글자는 사진을 넣을 때 사람이 확인한다(`assets.md` 확인 항목)
- [x] 밝은·어두운 화면에서 대체 배경이 히어로답게 짙고, 그 위 글자가 읽힌다(임시 확인 화면 스크린샷, 사람 확인)
- [x] `docs/design/photo-candidates.md`에 자리별 후보가 있고, 메인이 눈으로 확인한 결과가 적혀 있다
- [x] `npm run check` 통과, 빌드 통과

## 결과 (2026-11-17)
- `HeroMedia`(대체 배경·사진+덮개), 사진 목록 `hero-photos.ts`(세 자리 모두 비어 있음), 기록 양식 `docs/design/assets.md`를 만들었다. 화면에는 아직 넣지 않았다
- 테스트 9개 추가(`HeroMedia.test.tsx`), 대비·이름 검사 3개 추가(`tokens.test.ts`). 전체 통과, 빌드 통과
- 임시 확인 화면(커밋하지 않고 지움)에서 세 자리를 밝은·어두운 화면으로 봤다. 확인하다 두 가지를 고쳤다
  - **`text-hero` 이름 겹침**: T-039의 글자 크기 토큰 `--text-hero`가 색 토큰 `--color-hero`와 겹쳐 `text-hero`가 히어로 색으로 해석됐고, 제목이 바탕과 같은 색이 돼 안 보였다. `--text-hero-title`로 바꾸고 색·크기 이름 겹침 검사를 넣었다(옛 이름이면 실패하는 것 확인)
  - **어두운 화면 그라데이션**: 끝의 틸이 너무 밝았다. 틸을 35%만 덮게 하고, 가장 밝은 곳에서도 히어로 글자가 4.5:1 이상인지 계산하는 테스트를 넣었다
- 사진 후보: fury가 Pexels 9장(자리별 3장)과 Unsplash 참고 3장을 찾았다. 메인이 Pexels 9장을 브라우저로 봤다. 사람 얼굴은 모두 없다. 1-B는 네트 받침 글자, 체크무늬 패들 3장(2-B·3-A·3-C)은 제품 디자인 오인 가능성으로 "주의"
- 남은 일: 사용자가 사진을 고르고 라이선스 원문 확인 → 승인 후 내려받기·WebP·기록(별도 커밋)
