# T-025 결과 공유(결과만)

## 목표
결과 화면의 추천 3개를 링크로 다른 사람(동호회 등)에게 보여 줄 수 있게 한다. **링크에는 제품 id만 담고 답변은 담지 않는다**(phase2 결정 5, 팔 불편 답은 건강 관련 정보, ui-flow 4장). 공유 방법은 "링크 복사" + 휴대폰 기본 공유 창(D6). 기획: docs/plan/m2.md 3장 B·9장 D6, phase2 4장 M2.

## 할 일
1. **공유 주소 만들기·읽기**(새 순수 함수 `src/lib/shared/share.ts`)
   - 주소: `{SITE_URL}/shared?p=id1,id2,id3`(순위 순서). 사이트 주소는 T-027의 `SITE_URL`
   - 만들기: 제품 id 1~3개만 받는다. 답변·프로필·점수는 받지 않는다(함수 인자 타입과 테스트로 막음)
   - 읽기: id 형식(`소문자·숫자·하이픈`)이 아닌 값은 버리고, 중복은 하나로, 최대 3개. 지금 목록에 없는 id는 "지금은 목록에 없는 제품"으로 따로 센다
2. **결과 화면에 공유 영역**(`Result.tsx`)
   - 하단 "답변 고치기·전체 둘러보기" 위에 "이 결과 공유하기" 영역: **공유하기**(휴대폰 기본 공유 창이 있을 때만 보임, `navigator.share`) + **링크 복사**(`navigator.clipboard`)
   - 공유 글: 제목 "패들핏에서 추천받은 피클볼 패들", 본문 "추천받은 패들 3개를 확인해 보세요."(제품 이름·답변·조건 칩은 넣지 않는다)
   - 복사하면 "링크를 복사했습니다" 안내(`role="status"`). 복사 기능을 쓸 수 없으면 주소를 읽기 전용 칸에 보여 직접 복사하게 한다
   - 공유 창을 사용자가 닫은 경우(취소)는 오류로 보이지 않는다
   - 조건을 바꿔 다시 찾은 결과(조건 완화)도 화면에 보이는 3개를 그대로 공유한다
   - 추천이 0개면 공유 영역을 보이지 않는다
3. **받은 사람 화면** `/shared`(새 페이지, 정적 빌드)
   - 주소의 `p`는 브라우저에서만 읽는다(`useSearchParams` + `Suspense`, 그동안 스켈레톤)
   - 제목 "공유받은 추천 패들", 안내 "공유한 사람의 답변은 담겨 있지 않습니다. 내 조건으로 받아 보려면 질문에 답해 주세요."
   - 제품마다 한 줄 행(둘러보기와 같은 모양) + 순위 숫자. 누르면 "제품 자세히" 시트(T-024). 비슷한 제품에서는 공유된 제품들을 뺀다
   - 목록에 없는 제품이 있으면 "N개는 지금 목록에 없는 제품입니다" 안내. 읽을 수 있는 제품이 0개면 "공유된 제품을 찾을 수 없습니다"
   - 제휴 링크가 있으면 제목보다 앞에 대가 표시(`AffiliatePageNotice`), 행에 "광고"(D-022)
   - 하단: 주 버튼 "나도 질문에 답하고 추천받기"(`/quiz`, 시작 버튼처럼 탭에 남은 답변을 지움) + "전체 둘러보기"
   - `noindex`(공유 주소마다 같은 빈 페이지가 검색에 잡히지 않게). sitemap에는 넣지 않는다
   - 공유 미리보기는 사이트 공통(정적 내보내기라 공유마다 다른 그림·제목은 만들 수 없다)
4. **테스트**
   - share: 주소 형식, 순서 유지, 형식이 틀린 id·중복·4개 이상 처리, 목록에 없는 id 세기, 만든 주소에 답변 키(experience·arm 등)가 없음
   - 결과 화면: 공유하기는 `navigator.share`가 있을 때만, 링크 복사 → 안내 문구, 복사 불가 → 주소 칸, 공유 글에 답변·제품 이름 없음, 취소는 조용히
   - 받은 사람 화면: 순서대로 행, 목록에 없는 제품 안내, 0개 안내, 행 누르면 상세 시트, "나도…"가 답변을 지움, noindex

## 결과 (2026-11-16)
- `src/lib/shared/share.ts`: `buildShareUrl(ids)`(제품 id 1~3개만 받음, `{SITE_URL}/shared?p=…`), `parseSharedIds`(형식이 틀린 값·중복 제거, 최대 3개, 목록에 없는 제품 수), 공유 글 `SHARE_TEXT`(제품 이름·답변 없음)
- 결과 화면: 하단에 "이 결과 공유하기"("추천된 제품만 담깁니다. 답변은 공유되지 않습니다."). "공유하기"는 `navigator.share`가 있을 때만, "링크 복사"는 복사 후 "링크를 복사했습니다.", 복사 불가면 주소 칸. 공유 창 취소는 조용히 넘어간다
- `/shared`: `useSearchParams` + `Suspense`(그동안 스켈레톤), 순위 숫자와 한 줄 행(`ProductRow`를 둘러보기와 같이 쓰게 꺼냄), 목록에 없는 제품 안내, 0개 안내, 행 → "제품 자세히" 시트(비슷한 제품에서 공유 제품 제외), "나도 질문에 답하고 추천받기"(탭의 답변을 지움, `StartButton`에 글자 인자 추가) + "전체 둘러보기", `noindex, follow`, sitemap 제외
- 테스트 369 → 381개. 팔 불편 답(`arm: yes`)을 넣은 답변으로 공유 주소·공유 글에 답변 키·값·제품 이름이 없는지 확인. `npm run check`·`npm run build` 통과
- 브라우저(정적 빌드, 375px): 이 환경의 브라우저에는 기본 공유 창이 없어 "링크 복사"만 보였고, 복사가 막혀(사용자 조작이 아닌 스크립트 클릭) 주소 칸이 나왔다. 주소는 `…/shared?p=joola-heat-vision-scorpeus-16mm,vatic-pro-v-sol-tour-bloom-16mm,nox-x-treme-tempus-16mm`. 이 주소를 열면 제목 "공유받은 추천 | 패들핏", 1~3순위 행, 가로 넘침 없음
- 알게 된 것: 제품 id가 길어 공유 주소가 140자 정도다. 카카오톡에서는 미리보기 카드로 보여 문제가 적을 것으로 보지만(미확인), 짧게 하려면 id 대신 짧은 코드가 필요하다(데이터에 필드 추가). 지금은 하지 않는다
- 확인하지 못한 것: 휴대폰 기본 공유 창과 카카오톡, 카카오톡 앱 안 브라우저의 복사, 실제 클릭으로 복사했을 때의 안내(이 환경에서는 클립보드 권한이 없음)
