# T-045 결과 화면 레이아웃

## 목표
결과 화면을 D-037 배치로 바꾼다. 순서는 헤더 → 대가 표시 → 짙은 히어로(제목) → 가로 조건 요약 줄 → 추천 카드 → 아래 행동 줄이다. 조건 요약 줄 옆의 "추천 기준 보기" 시트에서 답변이 어떤 스펙 기준이 됐는지 보여 준다. 기획: docs/plan/m2.5-redesign.md 2장 결과 행·3.4·3.6·4.4, 7장 T-045 행, D-037.

## 화면 순서 (모바일·데스크톱 같은 DOM 순서, 시각 재배치 없음)
1. 공통 헤더(T-040)
2. **대가 표시**(제휴 링크가 있을 때): 지금 그대로, 히어로보다 앞
3. **히어로**(`HeroMedia` 결과 자리, 대체 배경)
   - 제목 `h1`: 결과 수를 반영한다. 예: "답변에 맞는 패들 3개를 찾았어요". "패들 3개"에 라임 밑줄
   - 결과가 없으면 "조건에 맞는 패들을 찾지 못했습니다"
   - 설명 한 줄: "답하신 조건과 공개된 스펙으로 고른 결과입니다."
   - "비교하기"(히어로용 테두리 버튼, 2~3개일 때)
   - 조건을 바꿔 다시 찾은 결과 안내, 개수가 적다는 안내는 히어로 아래로 옮긴다(글자색 대비 때문에 밝은 바탕에 둔다)
4. **가로 조건 요약 줄**
   - 지금의 조건 칩(경력·성향·무게·형태·예산·대회. 팔 불편은 지금도 없음)과 "고치기"
   - 오른쪽에 "추천 기준 보기" 버튼
5. 팔 불편 안내(해당할 때): 지금 문구 그대로
6. **추천 카드**: 1순위 큰 카드 + 2·3순위 줄(지금 구조). 카드 영역은 본문 전체 폭이다. 데스크톱 3열은 T-046에서 한다
7. 조건 완화 제안, 결과 없음 안내, 그립 안내, 바닥 안내 문구: 지금 그대로
8. **아래 행동 줄**: 답변 고치기 · 전체 둘러보기 · 공유. "결과 저장"은 T-050에서 넣는다

## "추천 기준 보기" 시트 (새 `ConditionSummary.tsx`)
- 제목 "추천에 반영한 조건". 답한 조건마다 "조건 → 기준" 한 줄로 보여 준다. 값은 기존 상수에서만 읽는다
  - 예산: 범위 밖이거나 가격 정보가 없는 제품은 뺀다(예산 범위)
  - 대회용: USA Pickleball 승인을 확인한 지 `CERT_MAX_AGE_DAYS`(180)일 안인 제품만
  - 플레이 성향
    - 컨트롤: 코어가 `LEAN.core.neutralMm`(15)mm보다 두껍고, 무게가 `LEAN.weight.neutralOz`(7.9)oz보다 가볍고, 넓은·표준형일수록 우선
    - 파워: 그 반대
    - 균형·모르겠음: 중간에 가까울수록 우선
  - 무게 선호: 고른 무게대(`WEIGHT_BAND` 7.3·8.4oz 경계)를 우선하고, 벗어난 만큼 낮춘다
  - 경력
    - 입문·중급이고 무게를 고르지 않았으면: 권장 무게대 7.3~8.4oz를 우선
    - 경력이 짧을수록 빗맞아도 덜 흔들리는 사양(넓은·표준형, 두꺼운 코어)을 더 중요하게 본다
  - 선호 형태: 고른 형태를 우선하되, 다른 형태를 빼지는 않는다
- 넣지 않는 것: 팔 불편 답, 가중치·점수 숫자
- 기준 문장을 만드는 함수는 화면과 떼어 순수 함수로 둔다. 테스트에서 상수 값과 같은지 확인한다

## 그 밖
- 1024px 이상에서는 하단 고정 구매 버튼(`StickyBuy`)을 숨긴다. 구매 버튼이 카드 안에 보이기 때문이다
- 본문 폭: 1024px 이상에서 최대 72rem(헤더와 같음). 모바일은 지금처럼 한 열이다
- 분석 중 화면, 엔진 호출 방식, 공유·비교 동작은 바꾸지 않는다
